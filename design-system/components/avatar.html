Avatar

A person, drawn as a circle or a square, at four sizes. The only component in this pass with no contrast failure anywhere.

Has gaps2 shapes4 sizesLight and darkFigma 60899:8165 ↗
This one is in good shape. Both themes are specified, both pass contrast comfortably, and the icon comes from the TrinityIcons font rather than an embedded SVG, so it can be swapped without rebuilding the component. The gaps below are about missing variants, not broken ones.

XSmall is the icon form only. Confirmed by Verifi Design and being annotated in the Figma file. Every XSmall example on this page is an icon for that reason — there is no image demonstration at 16px because there is no permitted use of one.

States

No interactive states are defined. An avatar inside a clickable row or menu inherits that control’s states; on its own it is a picture.

Behaviour

  • Pick one shape for a product and keep it. Circles and squares mixed on one screen read as two systems.
  • The icon is a font glyph, not an embedded SVG, so a different icon can be dropped in without touching the component. That is also how the no-photo case is handled: there is no initials variant, and there is not meant to be one.
  • Do not put a photograph in the XSmall avatar. At 16px a face is a smudge. Confirmed by Verifi Design, and being annotated in Figma — XSmall is the icon form only.
  • The image fills the frame and crops to the centre. There is no focal point control.

Guidelines

Do

  • Choose one shape per product.
  • Use the icon form when there is no photograph. It is the intended fallback, not a placeholder.
  • Match the size to the density of what surrounds it.

Do not

  • Do not mix circle and square avatars in one interface.
  • Do not use a photograph at XSmall. Use the icon form.
  • Do not stretch an image to fit. It crops, by design.
  • Do not rely on the avatar alone to identify someone. Put the name near it.

Accessibility

Both themes clear the 4.5:1 requirement with a wide margin. No other component in this pass can say that.

Icon on background, light#FFFFFF#17161418.08:14.5:1Pass
Icon on background, dark#171614#F0EEEA15.61:14.5:1Pass
  • An avatar that carries meaning needs alt text with the person’s name. A decorative one beside a visible name takes alt="".
  • The icon form is decorative when a name sits next to it. Do not announce “user icon” twice.
  • If the avatar is the only way to tell two people apart, that is a failure regardless of contrast. Show the name.
  • An avatar inside a link or button must not swallow that control’s accessible name.

Known gaps

One question already closed. Photographs are not allowed in the XSmall avatar — it is the icon form only. Confirmed by Verifi Design and being annotated in the Figma file.
  • Icon size was only found at Large (TrinityIcons 24). Whether Medium, Small and XSmall have their own icon sizes or scale a 24px glyph is unconfirmed.
  • No initials variant. Verifi Design’s position is that the icon already covers the no-photo case and the icon itself can be made clearer. That is a legitimate choice, so the open question is narrower: initials distinguish two people apart in a list where a generic icon cannot, so decide whether a list of people is a case this component has to serve.
  • No group or stacked variant, and none is planned. Verifi Design has deprioritised it. If you need to show several people at once, list them rather than stacking them — do not build a stack locally, because the overlap rule, the order and the overflow count would all be yours to invent.
  • No status dot overlay, even though Badge defines a dot that would fit.
  • No image crop, focal point or aspect rule.
  • No broken or missing image fallback.
  • No border or ring. An avatar on a dark photograph has no separation from it. Verifi Design has accepted this and a ring is planned. It stands on its own now that the stacked group is deprioritised.
