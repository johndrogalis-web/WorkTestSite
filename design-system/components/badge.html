Badge

A small chip carrying a count, a word, or nothing at all. Three content types, four styles, and a dot that now carries a 1px ring so it survives a light page.

Has gaps3 content types4 stylesLight and darkFigma 60895:44879 ↗
The dot got its ring. Figma now gives every dot a 1px stroke on its own token, badge/dot/stroke — page ink in light, near-white in dark — so the shape has an edge whatever colour fills it. That closes the two light-mode dot failures from the last pass. The dot styles were also renamed to match the display styles: Default, Alternate, Error. What is still open is the Outline border, unchanged at #41A8F2.

States

Badges have no interactive states, and that is the definition rather than an omission.

A badge has no interactions. A chip does. Verifi Design’s rule: a badge is a displayed item that reports the current state of something and nothing more. The moment it can be clicked, hovered, selected or dismissed, it is a chip and belongs to that component instead. That single test decides which one you want, and it is the reason no hover, focus or pressed state will ever be added here.

Behaviour

  • The number badge caps at 40px, which fits three characters. Anything above 99 is written “99+”.
  • The text badge has no width cap at all, by deliberate choice — the designer split it into its own variant so the number could keep its cap.
  • Only Error changes between themes, for a measured reason. The light error chip #B00100 reaches only 2.23:1 against the dark surface, so it flips to #EFADAC at 8.80:1. The other three backgrounds are light enough to work in both modes and do not change.
  • The dot is visible in both themes because of its ring, but which dot it is still comes down to colour alone. Nothing else about it varies.

Guidelines

Do

  • Write the number. A dot says something happened; a number says how much.
  • Use Error for counts that need action, not for counts that are merely high.
  • Keep one badge per object. Two badges on one row is a layout problem, not a status problem.

Do not

  • Do not make a badge clickable, hoverable or dismissible. That is a chip.
  • Do not rely on the dot’s colour to say which state it is. Default, Alternate and Error look alike to a fair share of people; the ring makes the dot visible, not distinguishable.
  • Do not invent a success or warning style. Neither exists.
  • Do not use Outline on a dark surface expecting it to adapt. It does not.
  • Do not put a badge on something that is not countable or not a status.

Accessibility

The text inside every badge is comfortably readable. The one remaining failure is a shape with no text in it: the outline badge’s border. The dot, which failed last pass, is measured on its ring now, because the ring is the boundary.

Why the ring, and not a darker fill. WCAG 2.x measures luminance and discards hue, which is unkind to the brand yellow: #E3F200 on the light page is 1.07:1 on paper however visible it looks. Recolouring the dot would have meant a second brand yellow. A ring in the page ink keeps the colour and gives the shape an edge that measures above 14:1 in both themes. One side effect to know about: in dark mode the ring and the yellow fill are both light, so the Default dot reads as a slightly larger pale dot. It is still clearly on the page.
  • A badge that changes on its own needs aria-live="polite" on its container, or the change is silent.
  • A dot needs role="img" and a label. “Unread” is a label; a bare <span> is not.
  • Write the count into the accessible name: “Notifications, 12 unread”, not “12”.
  • Never let colour alone distinguish Error from Default. The word or the number has to do it.

Known gaps

Nothing here blocks a build. Size, colour, wrapping, placement of the ring, naming and the badge-versus-chip rule are all answered above. What follows is housekeeping and two open decisions.
Closed this pass. The dot has a 1px ring on badge/dot/stroke, so both light-mode dot failures are gone. The dot styles are renamed Default, Alternate and Error to match the display styles. Figma’s note on the dot now says the fill and stroke are variable-bound presets and should only be overridden for a documented exception.
  • The Outline border still measures 2.59:1, below the 3:1 a boundary needs. Unchanged since the first pass and now the only contrast failure on the page.
  • The Default background is still bound to badge/dot/fill/default — a dot token reused for the chip. Verifi Design is checking that variable.
  • One token name lags the rename. The Alternate dot is still filled by badge/dot/fill/Information. Cosmetic, but it will confuse the first developer who reads the tokens.
  • No success or warning style. Verifi Design’s leaning is one reusable badge whose colour can be set, rather than a growing list of named styles — which makes the colour-pair problem on Tag worth solving first, since it would arrive here too.
  • The 20px height and 4px padding only work at line-height 1, but the type token says 1.3. One of the two is wrong.
  • No placement rule — anchored to an icon, inline with text, in a tab header. All undefined.
  • Still no stated relationship to Truck phase tag. Both are non-interactive status displays, so the badge-versus-chip test does not separate them; something else has to.
