Verifi Design System/Components/Badge

Badge

A small chip that shows a status: a count, a word, or a coloured dot. It never does anything when clicked, because it is not a control. Three content types, four styles, light and dark, every colour pair passing.

Solid3 content types4 stylesLight and darkFigma 60895:44879 ↗
One test tells you whether you want a badge. Does it do anything when you click it? If no, it is a badge. If yes — it filters, opens, selects or dismisses — it is a chip, which is a separate component. Everything on this page follows from that.

Anatomy

A badge is a rounded chip with one thing inside it. Which thing decides the content type.

  • NumberA count, capped at 40px wide so it fits “99+” and nothing longer
  • TextA short word. No width cap; the chip grows to fit
  • Dot8 × 8, no text, with a 1px ring inside its edge so it stays visible on any page
  • Shape20px tall, 16px corner radius, 8px padding left and right
  • TypeABC Repro Medium 12px
  • StyleDefault, Alternate, Outline or Error. These are levels of emphasis, not meanings — the word carries the meaning

States

A badge has no states. It does not respond to hover, focus or press, and no such states will be added, because a badge that responds is a chip.

Behaviour

  • A number badge is capped at 40px. Anything above 99 is written “99+”.
  • A text badge grows to fit its word. Keep the word short; one or two words, never a sentence.
  • Only the Error style changes between themes. Light red on a dark page measured 2.23:1, so it becomes a pale red with dark text instead. The other three styles stay the same in both.
  • The dot is always visible because of its ring, but which dot it is still comes down to colour. Never rely on the dot alone to say something important.

Where it goes

Four places, one rule each. Pick by what the badge belongs to.

Belongs toWhereRule
An icon (notifications, inbox)Top-right corner, overlapping the iconCentre the badge on the icon’s top-right corner, pulled in by about a quarter of its width. Number or dot only, never a word. The icon’s click area does not grow.
A line of text (a menu item, a card title, a heading)After the text, on the same line8px gap, centred on the text. One badge per line.
A table cellLeft-aligned in its own columnThe column header names the status (“Unit status”, “Update”), so the badge only shows the value. Do not mix badges and plain text in one column.
A tabAfter the tab labelA dot means “something changed here”; a number means “this many”. Do not use Error in a tab; the tab is not the thing that failed.

Using a colour the library does not have

Badge is one of the few components built to be extended. A screen may need a status the four styles cannot say — a success, a warning, a category. The answer is not to wait, and not to detach the component. Three rules keep it safe.

  • Change only the fill, the text colour and the border. Shape, size, padding, type and the ring stay as they are. If anything else needs to change, it is not a badge.
  • Check the colours before using them. Text on the fill must reach 4.5:1, and a border must reach 3:1 against the page. Check both light and dark. A pair that fails in one theme is not ready in either.
  • Bring it back to the library. A colour that earns its place on a screen is proposed to Verifi Design as a named style with a token, so the next screen gets it for free. The four styles are not the last four; new ones arrive together, not one screen at a time.

Badge or Truck phase tag

Truck phase tag is for the phase of a truck and nothing else. Every other status is a badge. If the value is one of the nine truck phases, it is a phase tag. If it is anything else — a unit’s state, an update’s progress, an ignition flag, a count — it is a badge. The two never share a column.

The product screens that show these values today were built before the library and will be rebuilt on it. This is where each value lands when they are.

ValueGoes toWhy
“To job”, “Pouring”, “Returning”Truck phase tagA phase of a truck.
“Active unit”, “Unlinked unit”, “Maintenance mode”BadgeThe state of a unit, not a phase of a truck.
“Complete”, “In progress”BadgeThe progress of an update.
“Ignition on”BadgeA flag on a unit.
“Unit U-100000 →”Neither — a chipIt opens something when clicked. The moment it does, it is not a badge.

Guidelines

Do

  • Write the number. A dot says something happened; a number says how much.
  • Use Error for things that need action, not for numbers that are merely high.
  • Keep one badge per object. Two badges on one row is a layout problem, not a status problem.
  • Let the column header or the label say what the badge is about, so the badge only has to say the value.

Do not

  • Do not make a badge clickable, hoverable or dismissible. That is a chip.
  • Do not rely on the dot’s colour to say which state it is. The ring makes it visible, not distinguishable.
  • Do not add a colour that has not been checked in both themes, and do not keep one to yourself. See using a colour the library does not have.
  • Do not expect Outline to adapt on a dark surface. It stays white on purpose.
  • Do not put a badge on something that is not a status or a count.

Specs

  • Height20px
  • Radius16px
  • Padding4px 8px
  • TypeABC Repro Medium 12px, line-height 1. The general type token says 1.3, but that is for paragraphs; a single-line chip sets its own height, and 20px only works at 1.
  • Number max width40px
  • Border1px, Outline style only. Token badge/display/outline/border = primary/600 #0975C3
  • Dot8 × 8
  • Dot ring1px, inside the edge. Token badge/dot/stroke: #171614 light, #F0EEEA dark. Inside, so the footprint stays 8px and the colour shows as 6px.

Accessibility

Every colour pair passes. Text is measured on the chip behind it. The dot is measured on its ring, because the ring is its edge. The Outline border is measured on the chip it edges, and also clears 3:1 against the light page (4.17:1) and the dark page (3.40:1).

Why the dot has a ring instead of a darker colour. The rule that measures contrast counts brightness and ignores hue, which is unkind to the brand yellow: on the light page it scores 1.07:1 however visible it looks. Recolouring the dot would have meant a second brand yellow. A ring in the page ink keeps the colour and gives the shape an edge that measures above 14:1 in both themes. One side effect: in dark mode the ring and the yellow are both light, so the Default dot reads as a slightly larger pale dot. It is still clearly there.
  • A badge that changes on its own needs aria-live="polite" on its container, or a screen reader never hears the change.
  • A dot needs role="img" and a label. “Unread” is a label; an empty <span> is not.
  • Put the count in the accessible name: “Notifications, 12 unread”, not “12”.
  • Never let colour alone separate Error from Default. The word or the number has to do it.

Known gaps

Solid, as a starting point. Every colour pair passes in both themes, placement and size are settled, the four styles are levels of emphasis with the word carrying the meaning, and the line between Badge and Truck phase tag is drawn. Nothing on this page blocks a build. Verifi is still discovering its full brand, so this can change — together, and always passing AA.

Figma housekeeping

Small tidy-ups in the design file. None of them change what the badge looks like.

  • badge/display/outline/border should point at primary/600. If the file still shows primary/400, switch it; the value on this page is the spec.
  • The Default background is bound to badge/dot/fill/default, a dot token reused for the chip. Same colour either way; rename when convenient.
  • The Alternate dot is filled by a token still named badge/dot/fill/Information. Rename to match the style.

What may come later

Success and warning styles, or a dot-plus-word content type, if the rebuilt status screens turn out to need them. Nothing is planned. The rule under Behaviour says how a screen adds a colour in the meantime and how it gets back into the library. The colour-pair problem on Tag should be solved first, because it would arrive here too.
