Verifi Design System/Components/Badge

Badge

A small chip carrying a count, a word, or nothing at all. Three content types, four styles, light and dark, and every colour pair now passes.

Solid3 content types4 stylesLight and darkFigma 60895:44879 ↗
The dot got its ring. Figma now gives every dot a 1px inside stroke on its own token, badge/dot/stroke — page ink in light, near-white in dark — so the shape has an edge whatever colour fills it. That closes the two light-mode dot failures from the last pass. The dot styles were also renamed to match the display styles: Default, Alternate, Error. The Outline border moves one step down the same ramp, from primary/400 to primary/600 (#0975C3), which takes it from 2.59:1 to 4.83:1 on the chip and clears the last failure on the page.

States

Badges have no interactive states, and that is the definition rather than an omission.

A badge has no interactions. A chip does. Verifi Design’s rule: a badge is a displayed item that reports the current state of something and nothing more. The moment it can be clicked, hovered, selected or dismissed, it is a chip and belongs to that component instead. That single test decides which one you want, and it is the reason no hover, focus or pressed state will ever be added here.

Behaviour

  • The number badge caps at 40px, which fits three characters. Anything above 99 is written “99+”.
  • The text badge has no width cap at all, by deliberate choice — the designer split it into its own variant so the number could keep its cap.
  • Only Error changes between themes, for a measured reason. The light error chip #B00100 reaches only 2.23:1 against the dark surface, so it flips to #EFADAC at 8.80:1. The other three backgrounds are light enough to work in both modes and do not change.
  • The dot is visible in both themes because of its ring, but which dot it is still comes down to colour alone. Nothing else about it varies.

Placement

Four positions, and the badge behaves the same in each. Pick by what the badge belongs to.

Belongs toWhereRule
An icon (notifications, inbox)Top-right corner, overlapping the iconAnchor the badge’s centre on the icon’s top-right corner, offset in by about a quarter of the badge. Number or dot only, never a word. The icon’s hit area does not grow.
A line of text (a nav item, a card title, a heading)Inline, after the text8px gap, vertically centred on the text’s x-height, never on the line box. One badge per line.
A table cellLeft-aligned in its own columnThe column header names the status (“Unit status”, “Update”), so the badge carries only the value. Never mix badges with free text in the same column.
A tabAfter the tab labelSame as inline text. A dot means “something changed here”; a number means “this many”. Do not use Error in a tab — the tab is not the thing that failed.

Badge or Truck phase tag

Truck phase tag is for the phase of a truck and nothing else. Every other status is a badge. That is the whole rule. If the value is one of the nine truck phases, it is a phase tag; if it is anything else — a unit’s state, an update’s progress, an ignition flag, a count — it is a badge. The two never appear in the same column.

The product screens that show these values today were built before the library and will be rebuilt on it. This is where each value lands when they are.

ValueGoes toWhy
“To job”, “Pouring”, “Returning”Truck phase tagA phase of a truck.
“Active unit”, “Unlinked unit”, “Maintenance mode”BadgeState of a unit, not a phase of a truck.

“Ignition on”BadgeA flag on a unit.
“Unit U-100000 →”Neither — a chipIt navigates. The moment it can be clicked it is not a badge.

Mapping a status to a style

The four styles are emphasis levels, not meanings. Meaning comes from the word.

Status is…StyleExample
Neutral, inactive or offOutlineUnlinked unit
Informational, in motionAlternateIn progress, Maintenance mode
Brand emphasis, or a countDefault12, New, Active unit
Needs action nowErrorFailed, Overdue

There is no success or warning style and no dot-plus-word content type. Whether the rebuilt screens need them is the one open Figma decision on this page, listed under Known gaps. Until it is made, write the word and use the emphasis table above — do not invent a green locally.

Using a colour the library does not have

Badge is one of the few components built to be extended. A screen may need a status the four styles cannot say — a success, a warning, a category — and the answer is not to wait, and not to detach. Three rules make that safe.

  • Change only the fill, the text and the border. Shape, size, padding, type and the ring stay as they are. If the badge needs anything else to change, it is not a badge.
  • The new pair passes AA before it is used. Text on the fill at 4.5:1 or better, and if there is a border, 3:1 against the surface it sits on. Measure both themes. A pair that fails in dark mode is not ready in light mode either.
  • Bring it back to the library. A colour that earns its place on a screen is proposed to Verifi Design as a named style with a token, so the next screen gets it for free. Nothing here says the four styles are the last four; it says new ones arrive together, not one screen at a time.

Guidelines

Do

  • Write the number. A dot says something happened; a number says how much.
  • Use Error for counts that need action, not for counts that are merely high.
  • Keep one badge per object. Two badges on one row is a layout problem, not a status problem.

Do not

  • Do not make a badge clickable, hoverable or dismissible. That is a chip.
  • Do not rely on the dot’s colour to say which state it is. Default, Alternate and Error look alike to a fair share of people; the ring makes the dot visible, not distinguishable.
  • Do not add a colour that has not been measured in both themes, and do not keep one to yourself. See using a colour the library does not have.
  • Do not use Outline on a dark surface expecting it to adapt. It does not.
  • Do not put a badge on something that is not countable or not a status.

Specs

  • Height20px
  • Radius16px
  • Padding4px 8px
  • TypeABC Repro Medium 12px, line-height 1. The type token’s 1.3 is for running text; a single-line chip sets its own height, and 20px only works at 1.
  • Border1px, Outline style only, badge/display/outline/border = primary/600 #0975C3
  • Dot size8 × 8
  • Dot ring1px, inside, badge/dot/stroke: #171614 light, #F0EEEA dark
  • Number max width40px

Accessibility

Every pair passes. The dot is measured on its ring, because the ring is the boundary; the Outline border is measured on the chip it edges, and also clears 3:1 against the light page (4.17:1) and the dark page (3.40:1).

Why the ring, and not a darker fill. WCAG 2.x measures luminance and discards hue, which is unkind to the brand yellow: #E3F200 on the light page is 1.07:1 on paper however visible it looks. Recolouring the dot would have meant a second brand yellow. A ring in the page ink keeps the colour and gives the shape an edge that measures above 14:1 in both themes. One side effect to know about: in dark mode the ring and the yellow fill are both light, so the Default dot reads as a slightly larger pale dot. It is still clearly on the page.
  • A badge that changes on its own needs aria-live="polite" on its container, or the change is silent.
  • A dot needs role="img" and a label. “Unread” is a label; a bare <span> is not.
  • Write the count into the accessible name: “Notifications, 12 unread”, not “12”.
  • Never let colour alone distinguish Error from Default. The word or the number has to do it.

Known gaps

Solid — as a starting point. Every colour pair passes in both themes, the dot has its ring, placement and line-height are ruled, the four styles are emphasis levels with the word carrying meaning, and the badge-versus-phase-tag line is drawn. Nothing on this page blocks a build.

Figma housekeeping, not gaps

  • badge/display/outline/border aliases primary/600. If the file still shows primary/400, rebind it; the value on this page is the spec.
  • The Default background is still bound to badge/dot/fill/default, a dot token reused for the chip. Same value either way; rename when convenient.
  • The Alternate dot is filled by a token still named badge/dot/fill/Information. Rename to match the style.

What may come later

Success and warning styles, or a dot-plus-word content type, if the rebuilt status screens turn out to need them. Nothing is planned; the rule under Behaviour says how a screen adds a colour in the meantime and how it gets back into the library. The colour-pair problem on Tag should be solved first, because it would arrive here too.
