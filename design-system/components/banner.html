Banner

A full-width strip under the page header for a condition that stays until it is resolved. Two layouts: Default with an icon, text and one action; Simple with one centred link.

Has gaps2 layouts14 banner/* tokensLight read, dark derivedFigma 38356:1239 ↗
What changed in this version (October 2026). New page. Banner is newly green in Trinity Design System John V: two layouts (Default, Simple), five booleans (iconBefore, showSubtitle, actions, dismissable, plus layout), all values on banner/* tokens. The rules for placement, stacking, role and dismissal are house rules written here for the first time.
What it is. The one place on a page for “something you should know before you start”. It does not pop, it does not time out, and it never blocks.

Top: Default layout — icon, heading, subheader, one action on the right. Bottom: Simple layout — one centred link and an optional dismiss. Both are full-width strips with no radius; they belong at the top of a page or a region, never floating.

Try it

Dismiss the Simple banner and it goes; Default stays until the condition behind it clears. Focus moves to the next sensible place, not to the top of the page.

The strip is role="status": it is announced once, politely, when it appears, and nothing about it interrupts. Use role="alert" only for a banner that means stop.

Anatomy

  • ContainerFull-width strip, #F6F4F2, 12px 22px padding, 24px gap between parts, radius 0. No border, no shadow.
  • Icon (Default, optional)24px, #171614. Boolean iconBefore. One icon, and it says what kind of message this is.
  • HeadingBody/md 16 Medium, tracking −0.32. The whole message in one line if you can.
  • Subheader (optional)Body/md 16 Regular, 8px under the heading. Boolean showSubtitle. The why, or the when.
  • Action (Default, optional)One medium Button, right-aligned. Boolean actions. Never two.
  • Link (Simple)Link/sm Medium 14, #0D598F, underlined, centred. The entire Simple banner is one link.
  • Dismiss (Simple, optional)Ghost icon button, 16px ×, 8px from the right edge. Boolean dismissable.

Behaviour

These are rules, not suggestions. Figma draws the two layouts. Everything below is the house rule for when a banner appears, where, and when it leaves. Build to this.
  • Where. Directly under the page header, full width of Main Content, above the Page Grid. Never inside a card, never over content, never at the bottom.
  • How many. One Default banner per page. If two conditions apply, the more severe one shows and the other waits. Simple banners may stack above it, newest first, to a maximum of two.
  • Appears. On load, with the page — no slide, no fade. If the condition starts while the page is open, it appears in place and pushes content down; it never covers anything.
  • Leaves. Default leaves when the condition clears, or when its action resolves it. Simple leaves on dismiss, and stays dismissed for that person until the message changes.
  • Action. One, and it does the thing the heading describes. “View plant”, “Schedule”, “Open”. Never “OK” or “Learn more”.
  • Simple is a link. The whole strip is the hit area. Tapping anywhere but the × follows the link.
  • Reads once. role="status" announces the heading and subheader when it appears. It is never re-announced on navigation within the page.
  • Narrow screens. Below 600px the Default banner wraps: icon and text on the first line, action full-width underneath. Simple truncates its link to one line with an ellipsis.

Guidelines

Do

  • Lead with the condition, in plain words: “Plant 2 is offline”.
  • Put the consequence or the deadline in the subheader.
  • Use the icon to say what kind: info, warning, success.
  • Keep it until the condition is gone.
  • Use Simple for anything a person is allowed to ignore.

Do not

  • Use it for confirmations — that is a Toast.
  • Put two actions in it. Pick one; the other goes on the page.
  • Colour the strip red or green. The icon carries the kind; the strip stays neutral.
  • Let it animate, bounce or blink.
  • Show a Default banner nobody can act on and nobody can close.

Accessibility

  • Role. role="status" (polite) by default. role="alert" only when the banner means work has stopped. Never both on one page.
  • Not a heading. The heading text is a <p> with weight, not an <h2>; it is a message, not a section.
  • Order. The banner comes first in the main region’s tab order after the page header, so a keyboard user meets it before the content it is about.
  • Dismiss. Accessible name “Dismiss”; on dismiss, focus moves to the next focusable element after where the banner was.
  • Not colour alone. The kind is carried by the icon and the words. The strip is the same colour for every kind.
  • Contrast. Text 16.5:1 and link 6.7:1 in light; 14.7:1 and 6.2:1 in dark. All pass AA. The link hover does not change colour (the obvious lighter blue measures 4.1:1 at 14px and fails); it thickens the underline instead.

Known gaps

  • Light only in Figma. The Banner frame has no dark-mode variant; the dark values here are derived from the site’s dark surfaces and flagged in Specs.
  • Action button mode mismatch. The action inside the Default banner resolves to button/primary/fill #E3F200 — the dark-mode primary — in a light frame. This page uses the light primary (#0975C3) per the Button spec. Worth fixing in the file.
  • No kind. Figma has no info / warning / success variant; the icon is a free slot. The house rule above uses the icon for kind and keeps the strip neutral.
  • Link Atom documentation sits on the Banner page in Figma (65835:47147). It is generic guidance, not part of the Banner; nothing from it was moved here.
