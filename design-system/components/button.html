The six variants at Large (40px). Primary is blue in light and the brand yellow in dark; Secondary and Link are neutral in both themes; the two Destructives are red.

Try it

These are real buttons. Hover for the fill change and the thin outer stroke, tab to one for the double focus ring, hold the pointer down for the pressed colour. The circle is an icon-only button: its fill is invisible at rest and appears on hover. Click the last two to see the loading state: the label hides, a spinner takes its place, and the width does not change.

Anatomy

  • ContainerA pill: radius/pill = 100px, fill from the variant, horizontal auto layout with a 4px gap between icon and label
  • LabelABC Repro Medium 14px, line height 130%, in every size. The label frame carries 1px of its own side padding, so text sits 17px from the edge at Large
  • Prefix and suffix iconOptional, 16px TrinityIcons glyphs in the label colour; 12px at Small. Either, both or neither
  • BorderSecondary and Destructive secondary have a 2px inside border; Destructive a 1px one. Primary, Accent and Link have none
  • Hover strokeA 1px ring in hover-outer-stroke, every variant
  • Focus rings2px inner stroke plus 2px outer stroke (border/focus). Fill stays at focus, which equals the resting fill
  • SpinnerLoading replaces the content with a 24px arc (spinner/medium) in the spinner colour; 16px at Small. The button keeps its width

Behaviour

These are rules, not suggestions. Figma defines how a button looks; Verifi Design has adopted established UX practice for how it behaves. Build to this.
  • One Primary per view. If two actions both feel primary, one of them is Secondary. If nothing completes the task, there is no Primary on that screen.
  • Labels are verbs: Add a truck, Export, Delete ticket. Never OK, Yes or Submit on its own. Two to three words; sentence case; no trailing punctuation.
  • A button does something; a link goes somewhere. If the result is navigation, use an anchor styled as text, not a Link button. The Link variant is a quiet button, not a hyperlink.
  • Destructive never fires on the first click when the loss cannot be undone. Open a Modal and put the Destructive button there, next to a Link Cancel. Destructive secondary follows the same rule when the step cannot be undone; when it can (remove a line you can add back), it may act at once.
  • Loading replaces the click, not the button. The button stays where it is, at the same width, so the user can see which action is in flight. Disable the rest of the form while it spins; never let a second submit through.
  • Buttons size to their label. Only stretch to full width on mobile action bars and modal footers, and then stretch every button in the row.
  • Order in a row: Primary on the right, Secondary or Link to its left, Destructive on the far left with space between. Keep that order on mobile by stacking Primary on top.
  • Disable only when the reason is visible on screen. A disabled button with no explanation is a dead end. If the user has to guess why, show the reason as help text or validate on click instead.
  • Icon-only buttons need a visible name somewhere. A Tooltip on hover plus aria-label for everyone else. Universal glyphs (close, add, search) may go without the tooltip.

Guidelines

Do

  • Use Primary once per screen, for the action the screen exists for.
  • Use Link for the quiet actions around a table or card.
  • Use Large on desktop, XLarge on mobile so the target is at least 44px.
  • Pair an icon with a label unless the icon is universal (close, add, search).
  • Disable a button only when the reason is visible on screen.

Do not

  • Do not put two Primary buttons next to each other.
  • Do not use Destructive for cancel or close; those are Link.
  • Do not use Destructive secondary to soften a delete that cannot be undone. Quieter is not safer.
  • Do not change a label while the button is loading.
  • Do not use Accent as a second Primary. It is a highlight, not a call to action.
  • Do not restyle a button locally. If a state is wrong, fix the token.

Accessibility

Every label passes AA in both themes, at rest, on hover and when pressed. Dark hover and pressed fills that are opacity blends are measured over layout/base; they also pass over layout/layer 1.

Disabled is exempt. WCAG 1.4.3 excludes inactive controls from the contrast minimum, so the #7F796C-on-#D0CEC8 disabled label (2.75:1) is not a failure. It does read as faint.

  • Render a real <button>. Never a div with a click handler.
  • Icon-only buttons carry aria-label; the glyph itself is aria-hidden.
  • Loading sets aria-busy="true" and keeps the accessible name; the hidden label still reads to a screen reader.
  • Disabled uses the native attribute so it leaves the tab order. If the reason matters, put it in text next to the button, not in a tooltip.
  • Focus rings are :focus-visible only. Pointer clicks must not show them.
  • Minimum target: 24×24 CSS px (WCAG 2.5.8). Large and XLarge clear it; Medium and Small clear it only with their horizontal padding — do not shrink them further.

Known gaps

None open. Button matches the Figma file in both themes, and every label, hover and pressed pair passes AA.

Recommended improvement, not a gap. The light Secondary border is #D0CEC8 on #F0EEEA, 1.36:1. That passes WCAG, which does not require a button boundary, but the fill matches the page, so on #F0EEEA a Secondary next to a Primary can read as plain text. Darkening button/secondary/border-default to at least #8F8A80 (3:1), or giving Secondary a fill a step off the surface, would make it read as a button. Until then, prefer Secondary on a white card where it matters.
