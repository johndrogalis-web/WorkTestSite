Button

A button causes something to happen. If pressing it only takes you somewhere, it is a link and it should look like one.

Solid144 variantsFigma 30033:78562 ↗
The thing that surprises people. The set has four variants, but open any real Hub screen and almost every button is the quiet outline pill — even the one that creates a ticket. A filled button means this finishes the task and closes what you are in. If you are adding a solid button to a page, you probably want an outline one.

In Angular

The Template and Styles above are what this component renders. The tokens arrive as CSS custom properties on the host, so a theme change never touches the component. The contract below assumes standalone components with the vf- prefix; change the prefix if the team uses another, and nothing else on this page moves.

SelectorInputsOutputsWhat it renders

States

StateWhat changes
DefaultThe variant’s base appearance.
HoverQuiet darkens its border and ink; filled variants drop to 88% opacity.
Focus2px outline in --strong at 2px offset. Never removed.
ActiveSame as hover. There is no separate pressed state.
Disabled42% opacity, pointer events off.
LoadingA variant on the set. Never drop a spinner in by hand.

Behaviour

Buttons do not navigate. If activating the element changes the URL without changing state, it is a link.

  • One primary per visual container, at most. Never two.
  • Danger pairs with a confirm step when the loss is permanent.
  • In a toolbar, buttons sit 10px apart. In a modal footer, 8px.
  • A button that repeats down a table is ghost, every time.

Guidelines

Do

  • Label it with the verb the user is doing — Export, Message driver.
  • Let the button be as wide as its label needs.
  • Use ghost for anything repeated.

Do not

  • Do not use a button for navigation.
  • Do not colour a button by severity. Only danger has a colour.
  • Do not use yellow. In the product, yellow is dark-mode selection, not a call to action.
  • Do not disable the submit button to communicate a validation failure — say what is wrong.

Specs

  • Height44px
  • Radius32px
  • Padding0 18px
  • Font14px / 500
  • Gap to icon8px
  • Gap between buttons10px toolbar, 8px modal footer
  • Transition0.14s. Nothing bounces.
  • Focus ring2px at 2px offset

Accessibility

  • Use <button type="button">. A clickable div announces nothing and is not keyboard reachable.
  • An icon-only button needs an aria-label. The tooltip is not a label.
  • A loading button keeps its accessible name and adds aria-busy="true".
  • Never remove the focus ring. Never replace it with a colour change alone — colour alone fails for anyone who cannot distinguish it.
  • Disabled buttons are removed from the tab order, which means the reason they are disabled has to be visible on the page.

Known gaps

  • 46% of the set’s non-text fills are hardcoded rather than bound to tokens. Generate CSS from the Figma file and you inherit values that will not follow a theme change.
  • Three sizes exist as variants but only the 44px large has published values. Everything in the Hub is the large.
  • No distinct pressed state. Active covers it.
  • There is no link component. Interim rule: inline links use #295CCC in light and white in dark, underlined at 2px offset.
