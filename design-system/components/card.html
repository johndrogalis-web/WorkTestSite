Card

A box that holds one unit of something: a truck, a ticket, a device. Three types, five states, a slot for the content, and a status strip for the Hub.

Has gaps3 typesLight onlyFigma 63493:8711 ↗
Work in progress in Figma, and it shows. The Cards page holds five sets: a general Card (three types, five states, desktop and mobile, with a content slot), an Input Card Header for selectable cards, three example card content layouts, a Component Card and a Status Card for the Hub. This page documents the general Card and the Status Card, because those are the two with tokens. Two things stop it being Solid: there is no dark mode at all, and the interaction colours are blues that exist nowhere else in Trinity.

Anatomy

  • Surface#FEFFFF, 8px radius, 1px border, 20px padding
  • Shadow0 5px 8px at 12% by default, 0 4px 12px on hover
  • ContentA slot. The three example layouts in Figma (truck status, detail, device status) show it in use; they are examples
  • Input headerFor a selectable card: a radio or checkbox on the right, an optional badge on the left, 22px tall
  • Status stripStatus Card only: a 31px band across the bottom, coloured by status, with one line of text
  • TypesNavigational (the whole card is a link), Static (nothing to press), Input (the card is a radio or checkbox)

In Angular

For developers. Nothing in this section changes how the Card looks or behaves. If you design in Figma or write the rules, you can skip it.

In the Angular code the Card is one ready-made piece. Every colour, size and state on this page is already inside it, so the person building a screen chooses from the settings below and never restyles anything.

  • What you type<vf-card>
  • What you can settype (one of: navigational, static, input), href or routerLink for navigational, selected and control (one of: radio, checkbox) for input, status for the strip
  • What it tells youselectedChange (boolean) for input cards
  • What it handles for youNavigational renders one <a> with the title first; input renders a <label> around a real input; static renders an <article>. Content is projected.

Behaviour

  • Decide what the card is before you draw it. If clicking it goes somewhere, it is Navigational and the whole card is one link. If clicking it chooses it, it is Input and the whole card is one radio or checkbox. If clicking it does nothing, it is Static and it never shows hover.
  • One action per card. A navigational card does not also carry buttons inside it; nested clickable things are the classic card bug. Actions go in a footer row on a Static card.
  • The content slot is the card’s business; the card supplies the frame and the states, nothing else.
  • Cards in a grid share one width and one ratio for any image at the top. A ragged grid is a layout problem, not a card problem.
  • Input cards behave as a radio group or a checkbox group: arrow keys move through radios, Space toggles checkboxes, exactly as the bare controls do.
  • The Status Card’s strip carries the status in colour and in words, never colour alone. Normal is quiet green text on a tint; Warning and Alarm are the solid status colours.

Guidelines

Do

  • Use a card when a set of things are peers and each one is a unit: trucks, tickets, devices.
  • Keep the whole card as the single target.
  • Use the Status Card for anything with a health state; do not rebuild the strip.

Do not

  • Do not put a button inside a navigational card.
  • Do not use cards for a list that would read better as a table.
  • Do not nest cards.
  • Do not invent a fourth type; Static covers everything that is not a link or a choice.

Specs

  • Radius8px (Status Card 8px; the Hub Component Card uses 20px, which is one of the open questions)
  • Padding20px
  • Border1px #DAD8D7; hover #00A1E0; selected #0C79A8
  • Surface#FEFFFF; selected #EEF9FF
  • Shadow0 5px 8px rgba(74,79,85,.12); hover 0 4px 12px
  • Focus2px ring #0C79A8, 4px blur
  • Strip31px, 10px 20px padding, ABC Repro Medium 14px
  • WidthsDesktop 240 in the set; Mobile variant full width. Real widths come from the grid

Accessibility

Text passes. The state colours are the problem: the hover border does not reach 3:1, and none of the interaction blues belong to the Trinity ramp, so there is no dark-mode value for any of them.

Border on surface#DAD8D7#FEFFFF1.42:13:1Decorative

Focus ring on the light page#0C79A8#F0EEEA4.20:13:1Pass
Card surface on the dark page#FEFFFF#211F1C16.41:13:1Wrong, not failing
  • A navigational card is one <a>. Its accessible name is the title, so put the title first inside it.
  • An input card is a <label> wrapping the real radio or checkbox; the card is the visual, the control is the control.
  • A static card is a <div> or an <article>. Give it a heading.
  • Hover is not a state anyone has to see; focus is. The focus ring passes on both surfaces.
  • The status strip says its status in words. The colour is a bonus.

Known gaps

Work in progress. Build against this page, and expect the colours to change. The structure is settled: three types, five states, a slot, an input header and a status strip. The colours are not.
  • No dark mode. Every card token is the same value in both modes, so the card stays white on the dark page. It needs surface, border and selected values on the neutral ramp: the same pattern as Accordion.
  • The interaction blues are not Trinity colours. #00A1E0, #0C79A8 and #EEF9FF come from somewhere else. Hover and selected should use the primary ramp (primary/600 and primary/50), which would also fix the hover border’s 2.92:1.
  • Two radii. The Card and Status Card are 8px; the Hub Component Card is 20px. Pick one.
  • Five sets on one page. Card, Input Card Header, card content, Component Card and Status Card. Component Card and Status Card overlap almost entirely; keep one.

Decided on this page

  • Three types and what each one is allowed to do.
  • One target per card; no buttons inside a navigational card.
  • The content slot is the card’s business; the examples in Figma are examples.
