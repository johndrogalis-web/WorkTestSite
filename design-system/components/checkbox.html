Verifi Design System/Components/Checkbox

Checkbox

An independent yes or no. Several can be true at once, and the change applies when the form is saved, not the moment it is clicked.

Has gaps12 variantsFigma 30515:78521 ↗
The third state is now called indeterminate in both places. The public set used to say intermediate and the private one isIndeterminate; both have been renamed in Figma. indeterminate is the word HTML, ARIA and CSS already use — input.indeterminate, aria-checked="mixed", :indeterminate — so the Figma property and the code property are finally the same string.
Use this component in prototypes rather than drawing a checkbox. Verifi Design’s note: the label is a toggle on the component, so you switch it off where you do not want one and edit it in one place where you do, instead of retyping it in every layout. It also carries light and dark with it, so a prototype switched to dark mode brings the checkbox along without any manual recolouring. The same instance is what the table row selector uses.
There is one checkbox size, not two. The box is 16 × 16. Around it sits a 24 × 24 frame that Trinity literally names touchpoint — invisible, and the only thing a pointer or a finger has to hit. So the 24 you can measure in a table row is not a larger checkbox; it is the target around the same 16px box. That is also exactly what WCAG 2.2 2.5.8 Target Size (Minimum), AA asks for. Draw the box at 16 and give it 24 of room; never scale the box to fill the target. Trinity’s own variables say it outright: checkbox/width and checkbox/height are 24 (spacing/medium/600), checkbox/padding is 4 (spacing/micro/100), and 24 less 4 a side is the 16px box.
The tick is a vector, not a font character. It is a 6 × 4 polyline sitting at (5, 6) inside the box — (0, 1.33) → (2.4, 4) → (6, 0) — stroked at 1px with round caps and joins. Both arms run at 48°, not 45, and the right arm is half as long again as the left. A &#10003; glyph or a rotated CSS border gets the angle, the weight and the arm ratio all slightly wrong, which is why the site used to look heavier than the Figma. Copy the path.

IndeterminateBox fills, an 8 × 1 dash instead of the tick. For a parent whose children are partly selected. It is a display state, never something a click produces.
HoverBorder darkens. The touchpoint, not the box, decides when hover starts.
Focus2px outline at 2px offset, drawn on the box.
Disabled42% opacity. The value stays visible.

Behaviour

A checkbox waits. Clicking it stages a change that something else — Save, Apply, Done — commits.

Checkbox or toggle? If flipping it changes the system immediately, with nothing to press afterwards, it is a toggle. A toggle inside a form with a Save button is a checkbox wearing a costume.
Checkbox or radio? If exactly one option may be true, it is a radio group. A single checkbox is also correct for one opt-in confirmation.

Guidelines

Do

  • Write the label as the positive statement — what is true when it is ticked.
  • Put the parent checkbox above its children and use indeterminate honestly.
  • Keep groups vertical. Horizontal checkbox rows are hard to scan.

Do not

  • Do not write a negative label. “Do not show returned concrete” makes an unticked box a double negative.
  • Do not use a checkbox for something that takes effect immediately.
  • Do not put more than about seven in one ungrouped list.

Accessibility

  • Use a real <input type="checkbox"> inside a <label>. Do not rebuild it from divs.
  • Set indeterminate in JavaScript — it is a property, not an attribute, and it cannot be expressed in HTML alone.
  • Group related checkboxes in a <fieldset> with a <legend>.
  • Space is the activation key. Enter must not submit from a focused checkbox.
  • The visible label is the accessible name. Do not add a different aria-label.

Known gaps

  • The private set still spells one property isDisabled where the public set says disabled. Same word, two conventions, one component.
  • The private set has a variant option spelled fals alongside false and true, and it is the option the indeterminate variants use. A third truth value that only exists as a typo.
  • The tick vector is still named Icon / Check / Temp in the component. Either it is the real one and the name should say so, or it is a placeholder and the shipped checkbox is carrying a temporary icon.
  • The focus ring sits at a different distance on the checkbox and the radio. The checkbox ring is 2px outside a 16px box; the radio ring is 4px outside its 16px circle, because the radio inputContainer is 20 × 20 where the checkbox one is 16 × 16. Two controls that sit side by side in the same form should focus identically.
  • No pressed state is drawn.
