Date picker

A Text field you can type a date into, with a calendar four pixels beneath it for when you would rather look. Single date, six rows, 224 pixels square.

Has gapsField + CalendarDay 11 variantsSingle dateLight read, dark derivedFigma spec 64764:71295 ↗Components 64761:69878 ↗
New page (October 2026). Net-new in Form Fields v2: Trinity had no calendar of any kind. Four written specs feed this page — Date Picker, Calendar, Calendar Header, Calendar Day — and it follows the same overlay rule as every menu in the set: absolutely positioned at input bottom + 4, field height unchanged.
What it is. The product deals in deadlines. This is how a deadline gets entered: typed when you know it, picked when you do not.

An Input Field with a calendar icon in the trailing slot, and a 224 × 224 Calendar at input bottom + 4. The 19th is Today (outlined), the 23rd is Selected (filled). The field is 82px tall whether the calendar is open or not.

Try it

Two routes in, both real. Type a date in the first field and tab out: a valid one fills the field, an invalid one turns it to Error with the format in the helper. Or click the calendar icon: arrows move between days, PageUp and PageDown move a month, Enter picks, Escape closes. The month label is announced as it changes.

Anatomy

Four pieces, nested. Net-new in Trinity: the product deals in deadlines, and the only date control before this was a text field with a DD/MM/YYYY placeholder.

  • Date PickerOrganism. An Input Field with a calendar icon in the trailing slot plus a Calendar placed absolutely at input bottom + 4. Every input token is inherited; a date is entry, not a separate field type
  • CalendarOrganism. Calendar Header (224 × 32) above a 7 × 6 grid (224 × 192): one row of weekday letters, five rows of dates. Always six rows, so the panel is a constant 224 × 224 and never resizes the overlay it sits in
  • Calendar HeaderMolecule. Two Icon Only Buttons (32px, chevron left and right) around a month label, “September 2026” written out. Composes the real button so the arrows inherit hover, focus and disabled
  • Calendar DayAtom, 32 × 32, one centred text node. Style = WeekDay, Date, Today; State = Default, Hover, Focus, Selected, Disabled. Selected draws a filled circle; Today an outlined one. Leading and trailing cells from the neighbouring months are empty and not interactive
One cell, three roles. Style decides what the cell is; State decides how it is being interacted with. Keeping the two apart is what lets Today also be hovered, focused or selected without a combinatorial explosion of one-off variants.

Behaviour

These are rules, not suggestions. Figma specifies the composition, the overlay rule, the fixed grid and the state table; the keyboard model, parsing and the range rules are house convention. Build to this.
  • Typing must stay possible. The calendar is a convenience. Anyone who knows the date types it faster, and a read-only field forces a slower route on them.
  • State the format in the helper, not only in the placeholder, because the placeholder disappears the moment the person types.
  • Parse generously, display strictly. Accept 23/9/26, 23-09-2026, 23 Sep 2026; show DD/MM/YYYY. Error only when nothing sensible can be read.
  • Open on the month that matters: the current value if there is one, otherwise today. Never January.
  • Six rows, always. The panel never changes height as the person pages through months, so nothing under it jumps.
  • Today is always marked when its month is in view, whether or not it is the selected date.
  • Out-of-range days are disabled, not hidden, and the month arrows disable at the range edge rather than vanish, so the control never moves under the pointer.
  • Keyboard inside the grid: arrows move a day or a week, Home / End jump to the row ends, PageUp / PageDown move a month, Enter picks, Escape closes. The month label is a live region.
  • Single date only. Ranges are not built and no range tokens exist. When they are, they extend Calendar Day’s Style axis and add a second month; nothing here changes.

Guidelines

Do

  • Keep the field typeable.
  • Put the expected format in the helper.
  • Set min and max when the product knows them (no deliveries in the past).
  • Open on the value’s month, or today.

Do not

  • Do not make the field read-only to force calendar use.
  • Do not shrink the day cell below 32px to fit more on screen.
  • Do not vary the number of rows by month.
  • Do not replace the header buttons with bare chevron icons; the states come from the button.
  • Do not build a range picker by placing two of these side by side.

Accessibility

Figma’s numbers, re-measured: selected text 7.39:1 on the filled circle; the selected circle 7.39:1 against the panel; today’s outline the same; weekday letters 6.24:1; day text on the hover fill 13.46:1. All clear. Today is marked with an outline as well as colour, so it reads without colour vision.

  • The field is a normal text input; the icon is a <button> with aria-haspopup="dialog" and aria-expanded.
  • The calendar is role="dialog" (non-modal: the page stays usable); the grid is role="grid" with row and gridcell, roving tabindex on the days.
  • Today carries aria-current="date"; the selected day aria-selected="true"; disabled days aria-disabled.
  • Each day has a full accessible name: “Wednesday 23 September 2026”, not “23”.
  • Weekday letters are decorative column labels and not focusable.
  • The month label is aria-live="polite" so paging is announced.
  • The cell is 32 × 32, above the 24 × 24 minimum target.

Known gaps

  • Dark values could not be read. The Calendar Day spec quotes dark numbers (selected 4.83:1, circle 3.74:1 against the panel); the file resolved in light. Dark panes are derived. Note that 3.74:1 for the circle is fine for a boundary but tighter than light.
  • Single date only. Ranges are deliberately not built and no range tokens exist. Scheduling and reporting will want one.
  • Available times is in the file but not documented. A time-slot list with its own header tokens sits on the Date picker page. It needs a spec before it is used.
  • Parsing, keyboard and min / max are house rules. Figma gives the overlay rule, the grid and the states, not the entry behaviour.
  • Week starts on Sunday here. The file does not say. Make it a setting.
