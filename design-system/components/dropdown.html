Dropdown button

A Button that opens a short menu of actions. Pick one and it runs; the label never changes to show what you picked.

Has gaps3 typesOpen / closedInherits Button + MenuFigma spec 64764:71139 ↗Components 64751:68123 ↗
What changed in this version (October 2026). This page was “Dropdown”, a value picker. Form Fields v2 splits that into Select (choose a value, show it) and this, Dropdown Button (pick an action, label unchanged). It composes the real Button and the shared Menu Container rather than redrawing either, so it has no tokens of its own.
What it is. The “Actions” button on a ticket, the “Create” button on a list, the “More” at the end of a toolbar. If the button would show a value after the pick, it is a Select.

A Medium Secondary Button with a caret in its trailing slot, and the shared Menu Container four pixels below it. The label says what the menu holds, and it never changes.

Try it

Three real dropdown buttons. Click to open; the caret flips. Arrow keys move, Enter runs the action and closes, Escape closes without running. Watch the label: it stays “Actions” whatever you pick. The line underneath says what ran.

Anatomy

  • ButtonA real Button instance, Medium (32px), with the caret in its trailing icon slot. Every colour token is inherited, so the three types stay in step with the rest of the system
  • CaretIcon Small 16, label colour. Down when closed, up when open — the second signal for the open state alongside the menu itself
  • MenuThe shared Menu Container, absolutely positioned at button bottom + 4, with Menu Items in its slot. Same container as Select, Search and Date picker
  • ItemsActions. An optional leading icon, a verb, an optional divider before a destructive action
Picking an action, not choosing a value. A Dropdown Button does not display a selected item. Clicking an option performs an action — share, move, archive — and the button label never changes to reflect it. If the label should show what was chosen, the component you want is Select. This is the clearest line in the set and the one most often crossed.

Behaviour

These are rules, not suggestions. Composition, the two axes and the state table are Figma’s; the keyboard model and the content rules are house convention. Build to this.
  • The label never changes. Not to the last action, not to a count, not to anything. If it should, use Select.
  • Items are verbs. Share, Move to plant, Archive. Not nouns, not states.
  • Destructive last, after a divider, in red. One per menu at most. It opens a confirm Modal when the loss cannot be undone, same as a Destructive button would.
  • Keep it short. Three to seven items. Past seven, the menu needs headings or the screen needs a redesign; a dropdown is not a navigation.
  • Disabled items stay visible, dimmed and skipped by the keyboard, so the person learns what is possible here. Hide an item only when it is never possible for this user.
  • Icons are optional and all-or-nothing within a menu. A menu with icons on some rows reads as if the others are missing something.
  • Secondary by default. Primary only when the menu is the screen’s main action (Create). Link for the overflow at the end of a toolbar.
  • Flip above when there is no room below, decided once on open. Keep the 4px gap.

Guidelines

Do

  • Use it for a short list of actions on the thing the person is looking at.
  • Name the button for the group: Actions, Create, More, Export.
  • Put the destructive action last, after a divider.
  • Use Secondary unless the menu is the main action.

Do not

  • Do not use it to choose a value — that is Select.
  • Do not let the label change to the last action taken.
  • Do not use it as navigation. A menu of places is a nav pattern, not a dropdown button.
  • Do not put a single item in a dropdown. That is a button.
  • Do not mix checkboxes into an action menu. Settings go in a drawer or a form.

Specs

  • ButtonMedium: 32px, padding 8 / 12, gap 4, radius pill. Secondary #F0EEEA with 2px #D0CEC8, label #171614, pressed #211F1C / #F6F4F2. Primary #0975C3 / white, pressed #0D598F. Link #F0EEEA, label #171614, pressed #211F1C
  • CaretIcon Small 16 in the label colour, trailing slot; rotates 180° when open
  • MenuMenu Container: #FFFFFF, 1px #7F796C, radius 16, padding 6, items gap 2, shadow 5%; at button bottom + 4; min-width the button, otherwise content
  • ItemsMenu Item: 30px rows, 34 focused, padding 6, radius 4, hover #DFDEDD; destructive text #B00100
  • Count3 to 7 items; one destructive at most

Accessibility

Everything on the button is inherited from Button, in both modes. In the menu, the destructive item at #B00100 on white is 7.37:1 and 5.48:1 on the hover row. The caret direction is a second signal for the open state, alongside the menu itself, so open does not rely on the menu being noticed.

  • The trigger is a real <button> with aria-haspopup="menu", aria-expanded and aria-controls.
  • The menu is role="menu"; rows are role="menuitem". Not listbox / option: nothing here is selected.
  • Opening moves focus to the first item; closing returns it to the button.
  • Keyboard: ArrowDown / ArrowUp, Home / End, type-ahead, Enter or Space runs, Escape closes, Tab closes and moves on.
  • A disabled item is aria-disabled="true" and skipped, not removed from the DOM.
  • The destructive item is red and last and after a divider, so its difference does not rest on colour.

Known gaps

  • Ghost or Link. The Dropdown Button spec names its third type Ghost; the Button tokens call it Link. This page says Link and reads the Link tokens.
  • Dark values could not be read; the button inherits Button’s dark set, which this site has. The menu’s dark values are derived.
  • Destructive item styling is not in Figma. The menu rows have no danger variant. This page uses #B00100 text after a divider, matching the Destructive secondary button.
  • Keyboard model and flip-above are house rules.
