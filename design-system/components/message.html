Verifi Design System/Components/Message

Message

An inline note that stays put: something is true, needs attention, finished, or failed. Four severities, a full panel and a one-line minimal form.

Has gaps4 severitiesFull and minimalFigma 37329:254 ↗
The inline cousin of Toast. A message sits in the page, next to the thing it is about, and stays until the situation changes. A Toast floats, confirms, and goes away. Same four severities, same icons, different job. The full message is an inverted panel — dark in light mode, light in dark mode — so it reads as a distinct object. The minimal form is one line of icon and text in the page ink.
A replacement is proposed. The Notification family (Toast, Banner, Inline × four statuses) is drawn in Figma as the single home for every system message, and would absorb this component. Until the team agrees, this page is the spec and nothing here changes.

The full message: icon, title, description, on the inverted surface. Only the icon colour changes with severity.

Anatomy

  • Panel16px radius, 16px padding, 16px gap. Inverted surface: black in light mode, white in dark
  • Icon24px, coloured by severity. Info uses the inverted ink; warning, success and error use their status colours
  • TitleABC Repro Medium 14px, inverted ink
  • DescriptionOptional. ABC Repro Regular 14px, in the soft inverted ink
  • Minimal formIcon and one line of text, 24px tall, 16px gap, no panel, page ink

In Angular

For developers. Nothing in this section changes how the Message looks or behaves. If you design in Figma or write the rules, you can skip it.

In the Angular code the Message is one ready-made piece. Every colour, size and state on this page is already inside it, so the person building a screen chooses from the settings below and never restyles anything.

  • What you type<vf-message>
  • What you can setseverity (one of: info, warning, success, error), title, description, minimal (boolean), live (boolean: set when the message appears in response to an action)
  • What it tells youNone. An action beside it is a separate button.
  • What it handles for yourole="status" for info and success, role="alert" for warning and error, only when live is true. The icon is aria-hidden; the title carries the severity in words.

States

A message has no interactive states. It is not pressed, hovered or dismissed; it appears when its condition is true and goes when it is not. If something can be done about it, the action is a Button or a link placed after the description, not inside the message component.

Behaviour

  • Message or Toast? If the user needs to see it whenever they look at that part of the page, it is a message. If it confirms something that just happened and can go on its own, it is a toast.
  • Four severities and only four. Info says something is true. Warning says something needs attention soon. Success says something finished. Error says something failed and is still failing.
  • The message sits directly above the thing it is about: above the form, under the table, at the top of the card. Never at the top of the page for something halfway down it.
  • Title first, in the past or present tense, naming the object: “Slump out of range”, not “Warning”. The description says what to do about it.
  • One message per region. Two conditions at once are one message with two lines, or the more severe one alone.
  • A message does not animate in. It is there when the page draws, or it appears in place when the condition changes.

Guidelines

Do

  • Name the object and the number: the truck, the load, the value.
  • Use the minimal form for a single line beside a field.
  • Let an error stay until it is fixed.

Do not

  • Do not use a message for something that just happened and needs no action. That is a toast.
  • Do not stack severities. Show the worst one.
  • Do not put the only copy of a value inside a message.
  • Do not use success for the default state of a healthy thing. Silence is the success state.

Accessibility

Light mode passes everywhere. Dark mode does not as Figma binds it, because the inverted panel turns white and two of the tokens on it do not follow.

Dark mode needs three token changes before this component is safe. The description token feedback/fill-overlay is the same light grey in both modes, so it vanishes on the white panel; the page uses #565147. The warning and success icons are the 500 shades, which are fine on black and fail on white; on the white panel they need the 700 shades or darker. The icon is never the only signal — the title says the severity — so this is a 1.4.11 failure, not a 1.4.1 one, but it is still a failure.
  • A message that is present when the page loads needs no live region; a screen reader reads it in place.
  • A message that appears in response to something the user did is role="status" for info and success, role="alert" for warning and error.
  • The icon is decorative. The title carries the severity in words.
  • Put the message before the thing it is about in reading order, so it is heard first.

Known gaps

Specified here; dark mode is what Figma still has to fix. The layout, the four severities, the minimal form and the message-versus-toast rule are all decided. What keeps it short of Solid is that three dark-mode tokens fail on the inverted panel.
  • Make feedback/fill-overlay mode-aware. Light grey on black in light mode; a dark soft ink on white in dark mode. The page specifies #565147.
  • Warning and success icons on the dark-mode panel. status/warning/500 and status/success/500 fail 3:1 on white. Bind the icon to a mode-aware alias that steps down to the 700 shade in dark mode.

Figma housekeeping

  • The description text property default is lorem ipsum. Replace it with a real Verifi sentence so instances read as product.
