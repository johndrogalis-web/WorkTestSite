Verifi Design System/Components/Modal

Modal

An interruption that requires a decision before anything else can happen. It takes the whole screen hostage, so it has to earn that.

Has gapsExtra small onlyFigma 37282:2485 ↗
Only one size is published. Extra small is the only variant drawn. There is no header or footer slot spec and no close-affordance spec. The sm / md / lg widths in the CSS below are our proposal, not published values.

States

StateWhat changes
OpenScrim fades in, panel appears. Focus moves into the panel.
ClosingBoth fade out; focus returns to whatever opened it.
ScrollingThe panel body scrolls, never the page behind it.

Behaviour

Modals are for confirmation and destruction. Not for reference content alongside a page — that is a drawer. Not for a large workflow — that is a page. Not for a message the user does not have to act on — that is a toast.
  • The page behind it must not scroll while it is open.
  • Escape closes it, and so does clicking the scrim — unless the user has entered data, in which case confirm first.
  • The destructive action is on the right, the safe one on the left.
  • Never open a modal from inside a modal.
  • The title is a question or a statement, never a single word like “Confirm”.

Guidelines

Do

  • Say exactly what will happen and to what — name the ticket, the truck, the load.
  • Label the buttons with the verb, not Yes and No.
  • Keep it to one decision.

Do not

  • Do not use a modal to show information the user did not ask for.
  • Do not stack modals.
  • Do not put a form longer than the viewport in one.
  • Do not make the only way out the close icon.

Specs

  • Radius16px
  • Padding20px
  • Max width400px (xs, the only published size)
  • Scrimrgba(54, 50, 45, .5)
  • Shadow0 14px 40px rgba(0, 0, 0, .24)
  • Action gap8px
  • Title16px / 500
  • Body13.5px / 1.5

Accessibility

  • role="dialog" with aria-modal="true" and aria-labelledby pointing at the title.
  • Focus moves into the panel on open — to the first control, or to the panel itself if there is nothing to focus.
  • Focus is trapped inside while it is open, and returns to the trigger on close.
  • Escape always closes. This is not optional.
  • Everything behind it gets inert or aria-hidden="true".
  • A destructive confirm should not autofocus the destructive button.

Known gaps

  • Only Extra small exists. Anything bigger is improvised.
  • No header or footer slot spec — nothing says where a title, a close button or a footer belong.
  • No close-affordance spec. There is no drawn close icon, and nothing says whether one is required.
  • Drawers are not a component at all, despite being the Hub’s main detail surface. The pattern is documented under Motion.
