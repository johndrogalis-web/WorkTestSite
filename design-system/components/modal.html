Verifi Design System/Components/Modal

Modal

An interruption that requires a decision before anything else can happen. It takes the whole screen hostage, so it has to earn that.

SolidOne sizeFigma 37282:2485 ↗
One size, one decision. A modal is a small panel that asks one question. Extra small, 400px wide, is the modal. Anything that needs more room is not a modal: reference content beside a page is a drawer, a workflow is a page. The larger widths in the CSS below are kept for the day a case is agreed, and are not to be used until then.

In Angular

For developers. Nothing in this section changes how the Modal looks or behaves. If you design in Figma or write the rules, you can skip it.

In the Angular code the Modal is one ready-made piece. Every colour, size and state on this page is already inside it, so the person building a screen chooses from the settings below and never restyles anything.

  • What you type<vf-modal>
  • What you can setopen, title, closeOnScrim (default true, set false when there is unsaved input), showClose (only when there is no Cancel)
  • What it tells youopenChange (boolean), closed (with the reason: escape, scrim or button)
  • What it handles for youUses the native <dialog> with showModal(): aria-modal, focus trap and inert background come free. aria-labelledby points at the title. Header, body and footer are projected slots.

States

StateWhat changes
OpenScrim fades in, panel appears. Focus moves into the panel.
ClosingBoth fade out; focus returns to whatever opened it.
ScrollingThe panel body scrolls, never the page behind it.

Behaviour

Modals are for confirmation and destruction. Not for reference content alongside a page — that is a drawer. Not for a large workflow — that is a page. Not for a message the user does not have to act on — that is a toast.
  • The page behind it must not scroll while it is open.
  • Escape closes it, and so does clicking the scrim — unless the user has entered data, in which case confirm first.
  • The destructive action is on the right, the safe one on the left.
  • Never open a modal from inside a modal.
  • There are always two ways out: Escape, and a button. The close icon is a third, and only appears when the footer has no Cancel — an information-only modal, for example. When it does, it is the Icon Only Button at 24px, 8px in from the top-right corner.
  • Content longer than the panel scrolls inside the body. The header and footer stay put. If it scrolls a lot, it is a page, not a modal.
  • The title is a question or a statement, never a single word like “Confirm”.

Guidelines

Do

  • Say exactly what will happen and to what — name the ticket, the truck, the load.
  • Label the buttons with the verb, not Yes and No.
  • Keep it to one decision.

Do not

  • Do not use a modal to show information the user did not ask for.
  • Do not stack modals.
  • Do not put a form longer than the viewport in one.
  • Do not make the only way out the close icon.

Specs

  • Radius16px
  • Padding20px
  • Max width400px. One size.
  • Close iconIcon Only Button, 24px, 8px from the top-right corner. Only when there is no Cancel.
  • Scrimrgba(54, 50, 45, .5)
  • Shadow0 14px 40px rgba(0, 0, 0, .24)
  • Action gap8px
  • Title16px / 500
  • Body13.5px / 1.5

Accessibility

  • role="dialog" with aria-modal="true" and aria-labelledby pointing at the title.
  • Focus moves into the panel on open — to the first control, or to the panel itself if there is nothing to focus.
  • Focus is trapped inside while it is open, and returns to the trigger on close.
  • Escape always closes. This is not optional.
  • Everything behind it gets inert or aria-hidden="true".
  • A destructive confirm should not autofocus the destructive button.

Known gaps

Solid, as a starting point. One size, a header, body and footer with a rule for each, two ways out always and a close icon only when needed, and a clear line between a modal, a drawer and a page. Verifi is still discovering its full brand, so this can change — together, and always passing AA.

Figma housekeeping

Things the design file still has to catch up on. None of them change what is specified here.

  • Add the close icon to the Extra small variant as a hidden-by-default layer, using the Icon Only Button.
  • Name the header, body and footer as slots so a title and actions drop in without re-drawing.

Decided against

  • Larger sizes. A modal that needs 560px or more is a drawer or a page. If a real case arrives, the size is added together, not on one screen.

Related, not this component

Drawers are the Hub’s main detail surface and are not a component yet. The pattern is documented under Motion; it belongs on its own page when it is built.
