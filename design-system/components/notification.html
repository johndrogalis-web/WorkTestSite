Verifi Design System/Components/Notification

Notification

One family for every message the system sends: a Toast that floats and leaves, a Banner that stays in the page, an Inline note beside a field. Four statuses. Replaces Toast and Message.

Solid3 patterns4 statusesLight and darkFigma 65794:9868 ↗
Solid, as a starting point. Approved by the team. This family replaces Toast and Message; both of those pages now point here. Verifi is still discovering its full brand, so this can change — together, and always passing AA.
What it is. One component, two dials. Pattern says where it lives and how long it stays: Toast floats and goes away, Banner sits in the page until the thing is resolved, Inline sits next to the field it is about. Status says what kind of news it is: Info, Success, Warning, Error. Same surface, same type, same icons; only the border and icon colour change with status.

Try it

Toast: press Save and watch it arrive, stay for a moment, and leave on its own; hover it and the timer pauses. Banner: dismiss it, and it stays gone until you reload, which is the point of a banner. Inline: finish the plant code and the note resolves itself.

Anatomy

  • SurfaceOne neutral fill for every status: #F6F4F2 light, #171614 dark. Status never changes the fill
  • Border1px inside, in the status colour. This and the icon are the only things that change between Info, Success, Warning and Error
  • Status icon24px Feather outline in the status colour: info, check-circle, alert-triangle, alert-octagon
  • TitleABC Repro Medium 16px (Inline: 14px), #171614 / white
  • BodyABC Repro Regular 14px, line height 130%, #565147 / #B6B1A5
  • DismissThe Icon Only Button, Medium, in the top right. A 32×32 target. Toast and Banner only
  • ActionOne Button, Secondary, Medium, on its own row below the text. Optional (showButton). Toast and Banner only
  • RadiusToast 16px; Banner and Inline 8px
  • PaddingToast and Banner 16px all round, 16px between rows, 12px between icon and text; Inline 12px all round, 12px gap
  • ShadowToast only: 0 5px 8px at 12% (light) or 24% white (dark). Banner and Inline are flat

Banner is not the site-wide bar. The rule is explicit: a Notification Banner fills its parent section and never the whole viewport. A tenant-wide announcement at the top of the window (an outage, a holiday schedule) is a different thing, a Website Banner, and pushes the page down. Never use one where the other belongs, and never put a Website Banner inside a modal.

In Angular

For developers. Nothing in this section changes how the Notification looks or behaves. If you design in Figma or write the rules, you can skip it.

In the Angular code the Notification is one ready-made piece. Every colour, size and state on this page is already inside it, so the person building a screen chooses from the settings below and never restyles anything.

  • What you type<vf-notification> for Banner and Inline; a NotificationService plus one <vf-notification-outlet> per app for Toast
  • What you can setpattern (one of: toast, banner, inline), status (one of: info, success, warning, error), title, message, action (label, optional), dismissible; the service takes show({ status, title, message, action? })
  • What it tells youaction when the button is pressed, dismissed when the X is
  • What it handles for youToast is role="status" (role="alert" for Error) inside a polite live region; the timer pauses on hover and focus and Error never times out. Banner is role="status" with the title as a heading. Inline is linked to its input with aria-describedby. Focus is never moved to a notification.

Behaviour

  • Pick the pattern by what the message is about. Something the user just did: Toast. Something true about this page or workflow: Banner. Something about one field: Inline.
  • Toast timing: 5 seconds, 8 with an action, never for Error. Hover or focus pauses the clock.
  • A Banner stays until its condition is resolved. If dismissing it would hide something the user still has to deal with, it is not dismissible.
  • Inline appears when the input is wrong or needs help, and leaves on its own when the input is right. It never needs an X.
  • One Banner per section. If two conditions apply, the more severe one shows and the other waits.
  • Toasts stack bottom right, newest at the bottom, three at most; the fourth pushes the oldest out.
  • The action is Secondary, never Primary. A notification should not compete with the page’s own call to action.

Guidelines

Do

  • Say what happened and what to do next, in that order.
  • Keep the title to five words and the body to one sentence.
  • Use Error only when something failed. A warning is something that will fail if ignored.
  • Put the Banner at the top of the thing it is about, not the top of the page.

Do not

  • Do not put anything in a Toast that the user has to remember. It will be gone.
  • Do not use a Banner as a sticky bar across the whole window.
  • Do not stack a Toast and a Banner for the same event. Pick one.
  • Do not colour the surface by status. The border and icon carry it; the surface stays neutral.

  • Surface#F6F4F2 / #171614, every pattern, every status
  • Status coloursInfo #0D598F / #41A8F2; Success #15322F / #2ECF1D; Warning #D85A00 / #FFBA0D; Error #D70100 / #EFADAC. Used for the border and the icon, nothing else
  • TypeTitle #171614 / white; body #565147 / #B6B1A5
  • RadiusToast 16; Banner, Inline 8
  • SizesToast about 420 wide; Banner and Inline fill; Inline 70 tall with a body, 48 without
  • ShadowToast: 0 5px 8px rgba(74,79,85,.12) light, 0 5px 8px rgba(255,255,255,.24) dark
  • TimingToast 5s / 8s with action / never for Error

One thing that passes and still looks wrong. Light-mode Success is #15322F, a green so dark it reads as black next to the ink title. It is 12.5:1, so it is not an AA problem; it is a recognition problem. Worth a look before this ships.
  • Toast lives in a polite live region so it is announced without stealing focus. Error toasts use role="alert".
  • A Banner’s title is a heading, so it appears in the page outline.
  • Inline is tied to its input with aria-describedby, so the error is read with the field.
  • The dismiss target is 32×32. Colour is never the only signal: the icon shape differs per status.

Known gaps

Nothing open. The team approved the family, the two-banner rule, and the retirement of Toast and Message. What is decided is on this page; what is left is Figma tidy-up and one colour worth a second look.
