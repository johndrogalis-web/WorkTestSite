Progress bar

An 8px bar that fills left to right. Eight variants, every one of them named by the value it shows.

Has gaps8 variantsLight and darkFigma 51692:17330 ↗
The unfilled track fails contrast in both themes. #DFDEDD measures 1.16:1 against the light page and #666054 measures 2.64:1 against the real dark surface. The filled part is fine; it is the empty part you cannot see. Detail under Accessibility.

Anatomy

  • TrackFull width of its container, 8px tall, 4px radius
  • FillSame height and radius, width set by the value
  • Height tokenprogress bar/height = 8, which is size/1
  • Radius tokenprogress bar/radius = 4, which is radius/sm
  • LabelNone. The bar carries no text of its own.

States

The component has no states. It is a readout, not a control — there is no hover, no focus, no disabled and no error variant.

There is no indeterminate state either. If you do not know how much work is left, this component cannot say so. Use the Spinner until Figma adds one.

Behaviour

  • The bar fills from the left edge and keeps its 4px radius on the fill as well as the track, so at very low percentages the fill reads as a short capsule rather than a sliver.
  • Nothing in Figma defines a transition, so the bar in this documentation jumps rather than animates. Do not read that as a decision.
  • There is no minimum visible width. At 0% the fill disappears entirely, which is what the 0% variant shows.
  • The bar has no intrinsic width. It takes the width of whatever contains it.

Guidelines

Do

  • Put the percentage or a count next to the bar if the number matters. The bar cannot say it.
  • Use it when you know the total amount of work.
  • Give it a sensible maximum width. A progress bar stretched across a 1600px screen is hard to read.

Do not

  • Do not use it for an unknown duration. That is a spinner.
  • Do not colour the fill to signal success or failure. No such tokens exist.
  • Do not build a striped or animated variant. Neither is in the system.
  • Do not rely on the track being visible. Today it is not.

Specs

  • Height8px
  • Radius4px
  • Track, light#DFDEDD
  • Fill, light#171614

Accessibility

WCAG 1.4.11 asks for 3:1 between a graphical object and what sits behind it, when you need to see that object to understand the control. For a progress bar that means the track, because the track is what tells you how much is left.

The dark track passes in Figma and fails in the product. The Figma demonstration frame sits on pure black, where the track reaches 3.37:1. The product surface is #211F1C, where the same colour reaches 2.64:1. The value was chosen against the wrong background.
  • Give the element role="progressbar" with aria-valuenow, aria-valuemin and aria-valuemax.
  • Give it an aria-label saying what is progressing. “75%” on its own tells a screen reader nothing.
  • If the bar is the only indication that something is happening, put the same information in text as well.

Known gaps

One question already closed. The two variants that used to be called progress7 and progress8 have been renamed to 5% and 0% in Figma.
  • The track fails contrast in both themes. One token change fixes it here and on Slider, which has the same problem.
  • No label or value text. The component has no way to display its own number.
  • No indeterminate state, so unknown-duration work has nowhere to go.
  • No status colours. There is no success, warning or error fill.
  • No size scale. One 8px height, everywhere.
  • No transition, easing or duration is specified.
  • The light and dark demonstration frame is named “Brand core palette” in the Figma layer tree rather than after this component.
