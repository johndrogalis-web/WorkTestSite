Radio group

Exactly one choice from a short list, with every option visible at once. Choosing one unchooses the others.

Try it

Click into the field above the group, then press Tab. Focus lands on the group once, not four times. Press the arrow keys — each one moves and selects in the same keystroke. Press Tab again and you leave the whole group in one press. Then try to get back to nothing selected; there is no gesture that does it.

Native <input type="radio"> with a shared name. The script here only narrates — every behaviour you can feel is the browser’s.

None of that is worth rebuilding. A shared name buys the single tab stop, the arrow-key navigation, the mutual exclusion and the group announcement. Every div-and-script radio group in the wild is an attempt to re-earn those four things, and most get the tab stop wrong.

In Angular

For developers. Nothing in this section changes how the Radio group looks or behaves. If you design in Figma or write the rules, you can skip it.

In the Angular code the Radio group is one ready-made piece. Every colour, size and state on this page is already inside it, so the person building a screen chooses from the settings below and never restyles anything.

  • What you type<vf-radio-group>
  • What you can setoptions (array of { value, label, disabled? }), value, name, label (the legend), disabled; implements ControlValueAccessor
  • What it tells youvalueChange
  • What it handles for youA <fieldset> with a <legend> and native <input type="radio"> elements in labels. Arrow keys move selection; that is the native behaviour and is not re-implemented.

States

StateWhat changes
UnselectedEmpty circle, 1px border.
SelectedThe border thickens to 4px on the inside. The centre stays the surface colour, so it reads as an 8px hole rather than an 8px blob.
HoverBorder darkens. The touchpoint, not the circle, decides when hover starts.
Focus2px outline at 2px offset.
Disabled42% opacity. Say why it is disabled.

Behaviour

Radios are for two to five options. Past five, the list becomes a scanning problem and a dropdown is kinder.

  • One option should be selected by default unless the choice is genuinely open. A group with nothing selected is a form the user can forget.
  • Never offer a way to unselect back to nothing. That is a checkbox.
  • Order the options by a logic the user can see — frequency, size, alphabetical. Not by how they came out of the database.

Guidelines

Do

  • Use a legend that states the question.
  • Keep options vertical, one per line.
  • Preselect the safest or most common option.

Do not

  • Do not use radios for a binary on/off that takes effect immediately — that is a toggle.
  • Do not use them for more than five options.
  • Do not mix radios and checkboxes in the same visual group.

Specs

  • Touchpoint24 × 24
  • Circle16 × 16
  • Border, unselected1px --strong
  • Border, selected4px --strong, inside
  • Centre, selected8 × 8 of the surface colour
  • Gap to label9px
  • Gap between options10px

Accessibility

  • All radios in a group share one name. That is what makes them a group to the browser and to assistive technology.
  • Wrap them in <fieldset> with a <legend>.
  • Arrow keys move between options and change the selection. Tab moves past the whole group, not between its options — this is standard and you should not override it.
  • A group with nothing selected puts every option in the tab order; a group with a selection puts only the selected one there. Preselecting is the friendlier default.

Known gaps

  • Two sets exist — Radio Button Input and Radio Button Item — and the division between them is not documented.
  • The Input set adds an isInverse axis the Item set does not have.
  • The radio inside a table row is 24 × 24, not 16.
