Search

Find or filter, with suggestions that appear as you type. A Text field with a magnifier, the shared menu beneath it, and a row that highlights what matched.

Has gaps6 states3 row variants5 casesLight read, dark derivedFigma spec 64764:71092 ↗Components 64751:67916 ↗
New page (October 2026). Built from Form Fields v2. Search was a field type on the old Text field page; it is now its own component with a Suggestion Row atom, five documented cases and the shared Menu Container overlay. The inline search bar is the same component with label and helper off, not a second one.
What it is. Search finds; Select chooses. If the person is typing to narrow a large or unknown set, it is Search. If they are picking from a list the product already knows, it is Select.

An Input Field with a magnifier in the leading slot. Suggestions use the same Menu Container as Select, at input bottom + 4, filled with Suggestion Rows grouped by category. The typed text is highlighted inside each result.

Try it

Type a truck number or a ticket prefix — try 45, TKT, zz for no hit, or leave it empty and focus it for recent searches. Suggestions group by category with a divider, the match is highlighted, and the last row in a group is Show more. ArrowDown moves into the list, Enter runs the search, Escape closes. The second one is the inline variant: label and helper switched off, same component.

Anatomy

  • FieldAn Input Field instance with the magnifier in the leading icon slot. Every border, background and state token is inherited; Search adds no field colours. A clear control appears in the trailing slot once there is a value
  • SuggestionsA Menu Container at input bottom + 4, holding Suggestion Row instances in its Items slot. Grouped by category with a divider between groups
  • Suggestion Row28px tall, 32px left padding so results align under their header, 6 right, 4 top and bottom, 8 between content. Three variants: Default (a result), Header (the category), Show More (the action at the foot of a group)
  • Prefix · Match · SuffixThree editable text segments in a result. The Match background hugs its own text in #C5E4FB with #032D3D ink, so the highlight stays aligned when the copy changes. An optional Description sits beneath in #666054
  • Inline variantNot a second component. Switch Show label and Show helper text off
Searching, not selecting. Search finds or filters; Select chooses from a known list. The difference shows in the suggestions: they appear as the user types, they are matched against what was typed, and picking one runs a search rather than setting a value.

Behaviour

These are rules, not suggestions. Figma specifies the field, the overlay, the row variants and the five cases, and says plainly that it documents appearance, not matching logic or keyboard. So the matching and keyboard rules here are house convention. Build to this.
  • Suggest after two characters and a 200ms pause. Earlier is noise; later feels slow. Never suggest on every keystroke without the pause.
  • Match on starts-with first, then contains. Rank starts-with above contains, exact above both. Highlight only the part that matched.
  • Group by what the thing is — Trucks, Tickets, Orders, Customers — in a fixed order, with a divider between groups. Five rows per group, then Show more.
  • Picking a suggestion runs the search. It does not fill the field and wait. The field shows what was searched, the results page shows the results.
  • Enter always works on the typed text, suggestions or not. The overlay is a shortcut, never a gate.
  • Empty focus shows recent. The last five searches, newest first, each removable. Clear all at the foot.
  • No hit says so and offers a next step. A blank overlay reads as broken.
  • The clear control appears with the first character and never moves the text. It returns focus to the field.
  • Inline search is the same component with label and helper off, usually in a toolbar or a top bar. Give it a visible placeholder that names the scope: “Search tickets”.

Guidelines

Do

  • Name the scope in the placeholder: what can be found here.
  • Group suggestions and keep the group order fixed.
  • Show recent searches on an empty focus.
  • Keep Enter working on the typed text at all times.
  • Use the inline variant in toolbars; keep the label on in forms.

Do not

  • Do not use Search to choose from a known list — that is Select.
  • Do not build a second inline search component. Toggle the label and helper off.
  • Do not rely on the highlight to make a result readable; it is supporting emphasis.
  • Do not show an empty overlay. No hit is a message.
  • Do not require a suggestion to be picked before a search can run.

Specs

  • FieldEvery Input Field token. Magnifier input/icon-default #171614, Icon Small 16, leading slot. Clear control 24px in the trailing slot
  • OverlayMenu Container at input bottom + 4px
  • Suggestion Rowheight 28; padding 4 top and bottom, 32 left, 6 right; content gap 8; radius 4
  • Row coloursheader #171614 Body/xs Medium; result #171614; match #032D3D on #C5E4FB (aliases primary/100 light, secondary/600 dark); action #0975C3; description #666054
  • Timing2 characters, 200ms debounce; 5 rows per group

Accessibility

Match text #032D3D on the highlight is 10.97:1; the action link #0975C3 on the menu is 4.83:1; descriptions at #666054 are 6.24:1. All clear. The field inherits Input Field’s numbers.

  • The field is role="combobox" with aria-autocomplete="list", aria-expanded and aria-controls; the overlay is role="listbox"; results are role="option"; headers are not options and are not focusable.
  • Wrap the whole thing in role="search" (or a <search> element) so it is a landmark.
  • Announce the count with a polite live region: “5 suggestions”, “No results”.
  • The highlight is <mark>, which screen readers may or may not announce; the result is fully readable without it.
  • Clear is a real button with a name, and focus returns to the field after it.
  • Inline variant: the placeholder is not a label. Give the input an aria-label that names the scope.

Known gaps

  • Dark values could not be read. The spec says the highlight aliases secondary/600 in dark; the file resolved in light. Dark panes are derived.
  • Matching logic, timing and keyboard are not in Figma, by its own statement. Everything under Behaviour is house convention.
  • The clear control is not drawn. Expected of any search field; this page adds it in the trailing slot.
  • Recent-search rows have no remove control in Figma. Added here.
