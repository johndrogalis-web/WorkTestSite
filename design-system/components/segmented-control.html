Segmented control

Two to five views of the same data, switched in place. Every segment is a Button: the selected one is Primary, the rest are Ghost, so the colours, sizes and states are the Button's in both themes.

Has gaps2 to 5 segments4 sizesLight and darkFigma 63396:1022 ↗
It is a row of Buttons, and it borrows everything from them. Each segment is the Button component, so size, hover, focus, disabled, light and dark all come from there and never drift. The selected segment is the Primary button, blue in light mode and the brand yellow in dark; the others are the Ghost button. Two to five segments, four sizes, one selected at all times.

Anatomy

  • SegmentsTwo to five Button instances joined edge to edge with no gap, the outer corners rounded to the pill, the inner ones square
  • Selected segmentThe Primary button, default state: #0975C3 with white text in light, #E3F200 with dark text in dark
  • Unselected segmentThe Ghost button, default state: #F0EEEA with ink text and a 1px ink border in light, #393632 with white text in dark
  • SizesXLarge 52, Large 40, Medium 32, Small: the Button sizes, set once for the whole group
  • LabelThe Button label; or one icon with the label as its accessible name
  • CountTwo is a toggle with words; past five, use Tabs or a Dropdown

In Angular

For developers. Nothing in this section changes how the Segmented control looks or behaves. If you design in Figma or write the rules, you can skip it.

In the Angular code the Segmented control is one ready-made piece. Every colour, size and state on this page is already inside it, so the person building a screen chooses from the settings below and never restyles anything.

  • What you type<vf-segmented>
  • What you can setsegments (array of { value, label, icon? }, two to five), value, size (one of: xl, lg, md, sm), label (the group name), disabled
  • What it tells youvalueChange
  • What it handles for youA role="group" aria-label of vf-button instances rendered as <button aria-pressed>: the pressed one is the Primary variant, the rest are Ghost. Exactly one is pressed. Icon-only segments need a label per segment. Not a radio group: this is a view switch.

StateWhat changes
SelectedThe segment is the Primary button. Exactly one, always.
UnselectedThe segment is the Ghost button.
HoverThe Button’s hover: the ghost fill darkens one step, the primary lightens. Pointer only.
FocusThe Button’s double ring: inner in the surface colour, outer in the ink.
PressedThe Button’s active state, for the moment the pointer is down. Then the segment becomes selected and the previous one becomes ghost.
DisabledThe whole group takes the Button’s disabled state. A single unavailable view is left out rather than disabled.

Behaviour

  • Segmented control or tabs? A segmented control switches between representations of one dataset: All tickets, Fleet map, Phases. Tabs switch between views of one object. If the page title stays and the content changes shape, this is the one.
  • Exactly one segment is always selected. There is no empty state and no deselect. On load, the first segment is selected unless the URL says otherwise.
  • Switching is instant and lossless. If moving away would discard input, this is the wrong component.
  • Put the selected segment in the URL so the view can be linked to, the same rule as tabs.
  • Segments size to their labels; they do not stretch to equal widths. Keep labels to one or two words.
  • Sits in the toolbar row, right-aligned, with the search field. One per toolbar.
  • Because every segment is a Button, a change to Button — a new size, a token fix — reaches every segmented control on its own. Do not override anything on the segment.

Guidelines

Do

  • Use it for two to five views of the same data.
  • Order the segments by how often they are used.
  • Keep one selected at all times.
  • Use Large in a toolbar, Medium inside a card.

Do not

  • Do not use it for actions. A row of Primary buttons is a button group, not this.
  • Do not use it as a form input. That is a radio group.
  • Do not put more than five segments in. Use Tabs or a Dropdown.
  • Do not restyle a segment. If a Button state is wrong, fix Button.

Specs

  • SizesButton sizes: 52 / 40 / 32 and Small
  • SelectedButton Primary, default: #0975C3 / white in light, #E3F200 / #171614 in dark
  • UnselectedButton Ghost, default: #F0EEEA / #171614, 1px #171614 border in light; #393632 / #FFFFFF, 1px #F6F4F2 border in dark
  • Radius100px on the outer corners of the group, 0 between segments
  • Gap0, with a −1px overlap so the borders share one line
  • Hover, focus, disabledFrom Button. Not redefined here
  • Motion0.14s, from Button

Accessibility

The selected and unselected segments both pass as text, and they are easy to tell apart, which is why the group mixes two Button types rather than using one type for all segments.

Why not one Button type for every segment. Figma’s set applies one type to the whole group and marks the selected segment with the Button’s active state. With Primary, active differs from default by 1.53:1 in light and 1.10:1 in dark, so the selected segment is not visible as selected. The Primary hover label also measures 2.59:1 on #41A8F2, which is a Button token problem and is logged there. Mixing Primary and Ghost keeps the theme colour the way you want it and makes the selection obvious.
  • Each segment is a <button aria-pressed> inside a role="group" with a label. Not radio inputs: this is a view switch, not a form value.
  • Tab moves between segments; Enter and Space select. Arrow keys are optional.
  • An icon-only segment needs an accessible name and a tooltip.
  • Colour is not the only signal: the pressed state is announced, and the fill difference is above 3:1 in both themes.

Known gaps

Specified here; one Figma change to make. Which set is the segmented control is settled: the Button-based SegmentControl (63396:1022) is canonical, and the older yellow pill set is retired. What the set cannot do yet is show one Primary segment among Ghost ones, because Type applies to the whole group.
  • Let the selected segment be a different Button type from the rest. Add a Selected property per position (or a selected index) that swaps that segment to Primary while the others stay Ghost. Until then, build to this page and read the Figma set for sizes and spacing only.
  • Button primary hover label is white on #41A8F2, 2.59:1. That is fixed on Button, not here; it is listed on the Button page.

Figma housekeeping

  • Retire the older Segmented Controls and Switch Item sets (56873:24205, 37702:166).
