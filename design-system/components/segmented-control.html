Segmented control

Two to five views of the same data, switched in place. One segment is always selected, and it is always the brand yellow.

Has gaps2 to 5 segmentsLight and darkFigma 56873:24205 ↗
One control, two Figma sets, and a decision the file has not made. The older Segmented Controls set is a pill of two to five segments with one selected in the brand yellow. The newer SegmentControl set (64 variants) is a row of joined Buttons in four types and four sizes with no selected state at all — a button group, not a segmented control. This page documents the pill, because it is the one that switches views, and treats the button group as a separate thing.

Behaviour

  • Segmented control or tabs? A segmented control switches between representations of one dataset: All tickets, Fleet map, Phases. Tabs switch between views of one object. If the page title stays and the content changes shape, this is the one.
  • Exactly one segment is always selected. There is no empty state and no deselect. On load, the first segment is selected unless the URL says otherwise.
  • Switching is instant and lossless. If moving away would discard input, this is the wrong component.
  • Put the selected segment in the URL so the view can be linked to, the same rule as tabs.
  • Segments size to their labels; they do not stretch to equal widths. Keep labels to one or two words so the control stays short.
  • Sits in the toolbar row, right-aligned, with the search field. One per toolbar.

Guidelines

Do

  • Use it for two to five views of the same data.
  • Order the segments by how often they are used.
  • Keep one selected at all times.

Do not

  • Do not use it for actions. That is a button group.
  • Do not use it as a form input. That is a radio group.
  • Do not put more than five segments in. Use Tabs or a Dropdown.
  • Do not use it and Tabs on one screen for the same job.

Accessibility

The selected segment passes easily. The unselected label is the problem: Figma binds it to text/subtle, which is 2.87:1 in light mode. The page uses the soft ink instead, which is what the hover state already lifts to a step further.

The border is decoration, and that is allowed. It measures under 1.3:1 in both themes, but the control does not depend on it: the selected fill and the labels carry the state, and the segments are readable as buttons without the outline. If the border ever has to do real work, it needs a token at 3:1.
  • Each segment is a <button aria-pressed> inside a role="group" with a label. Not radio inputs: this is a view switch, not a form value.
  • Tab moves between segments; Enter and Space select. Arrow keys are optional.
  • An icon-only segment needs an accessible name and a tooltip.
  • Yellow on dark text is the only colour signal for the selected segment, so aria-pressed is what makes it work for everyone else.

Known gaps

Specified here; two decisions still sit with Figma. Everything a builder needs is on this page. What keeps it short of Solid is that the file holds two different components under this name, and one token fails.
  • Which set is the segmented control. This page says the pill (Segmented Controls, 56873:24205). The 64-variant SegmentControl built from Buttons has no selected state and is a button group; it should be renamed or retired so the two stop competing.
  • The unselected label token. text/subtle is 2.87:1 in light mode (open item 03). Bind the label to border/soft or a darker text token; the page uses #565147.

Figma housekeeping

  • The Switch Item state property has both default and Default; merge them.
