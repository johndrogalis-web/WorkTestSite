Select

Choose a value from a list, and show the choice. A field with a caret, a menu that floats 4px beneath it, and a multi-select that is the same field with a different menu.

LearnWhen to reach for it, and a live one to try.

When to use

Use it for

  • Choosing one value from a list that is too long for radios: a plant, a status, an owner.
  • Choosing several values when the field only needs to show how many.
  • Any choice the field should keep showing after it is made.

Use something else when

  • Picking an action, such as share or archive. Use a Dropdown button.
  • Two to five options that fit on screen. Use a Radio group.
  • Free text with suggestions. Use Search.
  • A date. Use the Date picker.
Choosing a value, not picking an actionUse Select when the person is choosing from a list — a state, a status, an owner — and the field then displays what was chosen. Use Dropdown Button when they are picking an action — share, move, archive — which never displays a choice. This is the single most useful distinction in the set.

Three real selects. Click or press ArrowDown to open; arrows move the focus ring; Enter chooses and closes; Escape closes without changing. Move the mouse back over your choice to see Selected and Hover together. The multi-select stays open while you tick; the third has the search header.

UnderstandWhat it does by itself, and the choices you make.

Behaviour

What a select does by itself. Nothing here needs a decision.

  • The menu is absolutely positioned, always, at trigger bottom + 4px. An open menu never pushes the form down. The 4px gap is deliberate: flush reads as one object and looks wrong; wider reads as a disconnected panel. Do not change it.
  • The menu overlays the helper text. That is intended. The helper is read before opening, not during.
  • Opening moves focus to the current choice, or to the first row if there is none. Closing returns focus to the trigger.
  • Selected and Hover are independent. A row can be both, and is, every time the person moves the mouse back over their choice. Collapsing the two into one axis is the most common way menu components go wrong.
  • Single-select closes on choice; multi-select stays open. Multi closes on click-outside or Escape, and the field says “3 selected”, never the list, because listing breaks the fixed field height.
  • Select-all is a real checkbox and behaves like one: indeterminate when some are chosen, all on when every row is.
  • Switch Has Search on past about ten options. Under that, a filter field is more friction than scrolling.
  • Flip above when there is no room below. Decide once on open; do not re-flip while open. Keep the 4px gap on the other side.
  • Group with a divider, not a heading, unless the groups genuinely need names. Headings are not options and must not be focusable.

Guidelines

The choices you make, and why.

Do

  • Use Select when the person is choosing a value the field will then display.
  • Use Select Field for the open composite in layouts; use Select on its own only when the menu is drawn elsewhere.
  • Use Multi-Select Field for many; summarise the count in the field.
  • Enable Has Search past ten options.
  • Keep the 4px gap and the absolute position.

Do not

  • Do not use Select to trigger an action — that is Dropdown Button.
  • Do not create select-specific colour tokens. Inheritance is the point.
  • Do not create a separate multi-select trigger. Use Select and swap the menu variant.
  • Do not place the menu inline in the layout flow.
  • Do not use Selected to mean hover. They are different things and people see both at once.
  • Do not detach Menu Container to change its options. Use the slot.
Building itAnatomy, options, states, numbers and code, for designers and developers.

Anatomy

Five pieces, nested. Select redefines no colours, Multi-Select redefines no field, and the menu is the same under every trigger.

  • SelectMolecule. An Input Field instance with a caret in the trailing icon slot. Every border, background and error token is inherited; there are no select-specific colour tokens, and there should never be any
  • Select FieldOrganism. Select plus a Menu Container placed absolutely at input bottom + 4. Is Open = True shows the menu and flips the caret. 82px tall either way
  • Multi-Select FieldOrganism. The same Select with the Menu Container in its MultiSelect variant: a select-all row, a divider, then Checkbox-content items. No separate trigger exists on purpose
  • Menu ContainerMolecule. Optional search header · optional select-all · divider · an Items slot. #FFFFFF on a 1px #7F796C border, 16px radius (the house surface radius, shared with toast and accordion), 6px padding, 2px between items, a 0 5px 4px shadow at 5%. Scrolls past 600px
  • Menu ItemAtom. Optional check · leading icon · text or Checkbox · count · trailing icon · caret, with an optional description beneath. 30px tall, 34 when focused. The check space is reserved on every row so text aligns

Accessibility

  • Trigger: a <button role="combobox"> with aria-haspopup="listbox", aria-expanded, aria-controls and aria-labelledby pointing at the Label.
  • Menu: role="listbox"; rows role="option" with aria-selected; multi adds aria-multiselectable="true".
  • Keyboard: ArrowDown and ArrowUp move, Home and End jump, typing jumps to a match, Enter selects, Space toggles in multi, Escape closes. Disabled rows are skipped.
  • Selection shows as the check or the ticked checkbox, not by colour alone.
  • On close, focus returns to the trigger and the new value is announced.
