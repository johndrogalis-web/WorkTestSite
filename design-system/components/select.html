Select

Choose a value from a list, and show the choice. A Text field with a caret, a menu that floats four pixels beneath it, and a multi-select that is the same field with a different menu.

Has gapsSelect · Select Field · Multi-SelectMenu Item 16 variantsLight read, dark derivedFigma spec 64764:71062 ↗Components 64751:67521 ↗
New page (October 2026). Built from Form Fields v2, which splits the old Dropdown into two things: Select (choose a value) and Dropdown Button (pick an action). This page is the first; Dropdown Button is the second. Five written specs feed it: Select, Select Field, Multi-Select Field, Menu Item and Menu Container. The Menu Container is the same molecule under Dropdown Button, Date picker and Search suggestions, so its rules are written once, here.
What it is. A Select displays what is currently chosen; a Dropdown Button never does. If the control shows a value after the person picks, it is a Select.

Anatomy

Five pieces, nested. The whole point of the stack is inheritance: Select redefines no colours, Multi-Select redefines no field, and the menu is the same molecule under every trigger in the system.

  • SelectMolecule. An Input Field instance with a caret in the trailing icon slot. Every border, background and error token is inherited; there are no select-specific colour tokens, and there should never be any
  • Select FieldOrganism. Select plus a Menu Container placed absolutely at input bottom + 4. Is Open = True shows the menu and flips the caret. 82px tall either way
  • Multi-Select FieldOrganism. The same Select with the Menu Container in its MultiSelect variant: a select-all row, a divider, then Checkbox-content items. No separate trigger exists on purpose
  • Menu ContainerMolecule. Optional search header · optional select-all · divider · an Items slot. #FFFFFF on a 1px #7F796C border, 16px radius (the house surface radius, shared with toast and accordion), 6px padding, 2px between items, a 0 5px 4px shadow at 5%. Scrolls past 600px
  • Menu ItemAtom. Optional check · leading icon · text or Checkbox · count · trailing icon · caret, with an optional description beneath. 30px tall, 34 when focused. The check space is reserved on every row so text aligns
Choosing a value, not picking an action. Use Select when the person is choosing from a list — a state, a status, an owner — and the field then displays what was chosen. Use Dropdown Button when they are picking an action — share, move, archive — which never displays a choice. This is the single most useful distinction in the set.

Behaviour

These are rules, not suggestions. Composition, positioning and the state machine are Figma’s; the keyboard model and the copy rules are house convention and binding for new work.
  • The menu is absolutely positioned, always, at trigger bottom + 4px. An open menu never pushes the form down. The 4px gap is deliberate: flush reads as one object and looks wrong; wider reads as a disconnected panel. Do not change it.
  • The menu overlays the helper text. That is intended. The helper is read before opening, not during.
  • Opening moves focus to the current choice, or to the first row if there is none. Closing returns focus to the trigger.
  • Selected and Hover are independent. A row can be both, and is, every time the person moves the mouse back over their choice. Collapsing the two into one axis is the most common way menu components go wrong.
  • Single-select closes on choice; multi-select stays open. Multi closes on click-outside or Escape, and the field says “3 selected”, never the list, because listing breaks the fixed field height.
  • Select-all is a real checkbox and behaves like one: indeterminate when some are chosen, all on when every row is.
  • Switch Has Search on past about ten options. Under that, a filter field is more friction than scrolling.
  • Flip above when there is no room below. Decide once on open; do not re-flip while open. Keep the 4px gap on the other side.
  • Group with a divider, not a heading, unless the groups genuinely need names. Headings are not options and must not be focusable.

Guidelines

Do

  • Use Select when the person is choosing a value the field will then display.
  • Use Select Field for the open composite in layouts; use Select on its own only when the menu is drawn elsewhere.
  • Use Multi-Select Field for many; summarise the count in the field.
  • Enable Has Search past ten options.
  • Keep the 4px gap and the absolute position.

Do not

  • Do not use Select to trigger an action — that is Dropdown Button.
  • Do not create select-specific colour tokens. Inheritance is the point.
  • Do not create a separate multi-select trigger. Use Select and swap the menu variant.
  • Do not place the menu inline in the layout flow.
  • Do not use Selected to mean hover. They are different things and people see both at once.
  • Do not detach Menu Container to change its options. Use the slot.

Accessibility

The trigger inherits Input Field’s contrast. In the menu: text on the hover row 13.46:1; selected text 6.91:1, and 5.58:1 when hovered; the container border 4.33:1 on the menu and 3.73:1 on the page; the item focus border 4.33:1. All clear. The divider is 2.14:1 and decorative on purpose: nothing depends on seeing it.

  • Trigger: a <button role="combobox"> with aria-haspopup="listbox", aria-expanded, aria-controls and aria-labelledby pointing at the Label. Not a native <select>, which cannot be styled to the spec; but it must do everything a native one does.
  • Menu: role="listbox"; rows role="option" with aria-selected; multi adds aria-multiselectable="true".
  • Keyboard: ArrowDown / ArrowUp move, Home / End jump, typing jumps to a match, Enter selects, Space toggles in multi, Escape closes. Disabled rows are skipped.
  • Selection is signalled by the check (or the ticked checkbox), not by colour alone.
  • Focus ring on the focused row is visible against both the white menu and the page.
  • On close, focus returns to the trigger, and the chosen value is announced because the trigger’s text changed.

Known gaps

  • Dark values could not be read. As with Text field: the specs quote dark numbers (divider 1.50:1 dark), but the file resolved in light. Dark panes here are derived and marked.
  • menu-item/text-count and text-description are named in the spec but did not resolve as variables. This page uses #565147 for both, matching helper copy elsewhere.
  • Flip-above is not in Figma. The file positions the menu below, always. What happens at the bottom of a viewport is a house rule on this page.
  • Type-ahead and Home / End are not in Figma. Expected of any listbox; house rule.
  • Indeterminate select-all is not drawn. The Checkbox has the state; the MultiSelect menu does not show it. Needed for “some selected”.
