Slider

A 4px track with a 24px ringed thumb, in single and range forms. Drag it roughly; type it exactly.

Solid8 positionsSingle and rangeLight and darkFigma 53714:4469 ↗
The track is the Progress bar’s track. Same colours, same 1px ring around it, same token. The ring is what makes the empty part of the track visible on the page in both themes; without it the track measured under 1.4:1. Everything else on this page — thumb, fill, bubble — was already right.

In Angular

For developers. Nothing in this section changes how the Slider looks or behaves. If you design in Figma or write the rules, you can skip it.

In the Angular code the Slider is one ready-made piece. Every colour, size and state on this page is already inside it, so the person building a screen chooses from the settings below and never restyles anything.

  • What you type<vf-slider>
  • What you can setvalue (number, or [min, max] for the range form), min, max, step (default 1), unit, label, disabled, ticks (boolean, only when steps ≤ 10); implements ControlValueAccessor
  • What it tells youvalueChange, valueInput (fires while dragging)
  • What it handles for youBuilt on a native <input type="range"> per thumb, visually hidden over the painted track, so keyboard, touch and aria-valuetext come free. Range thumbs are clamped so they never cross.

Drag it, or tab to it and use the arrow keys. Both panes are live, so you can see the hover ring, the active ring and the value bubble behave in each theme rather than taking the screenshots on trust.

A real <input type="range"> sits invisibly on top and the painted parts mirror its value, so keyboard, touch and screen readers work without being rebuilt. Arrow keys move by 1, Page Up and Page Down by 10, Home and End jump to the ends — all browser defaults, none of them specified in Figma.

The focus ring you see here is the spec. A 3px ring in the theme’s selection colour around the thumb, shown only for keyboard focus. Not drawn in Figma yet; build to this.

Two states Figma has not drawn, both specified here. Focus: the 3px ring above. Disabled: the whole control at 42% opacity, the same as Toggle, and the thumb does not move. Say what would enable it.

Behaviour

  • The fill runs from the left edge to the thumb. On the range variant it runs between the two thumbs.
  • The value bubble appears above the thumb while the thumb is active, and shows the current number.
  • The step is set per use and defaults to 1. Arrow keys move one step, Page Up and Page Down move ten, Home and End go to the ends. These are the browser’s own rules for a range input, adopted as the spec.
  • The minimum and maximum are always written at the ends of the track, with the unit — “0 in”, “12 in”. Tick marks only when there are ten steps or fewer; past that they become noise.
  • On the range variant the thumbs can meet but never cross. The minimum gap is one step. When they touch, the fill between them disappears.
  • The value bubble looks like a tooltip and shares its height and radius tokens, but it is not the Tooltip component: it has no arrow logic and no delay. Its colour changes hue between themes on purpose — amber in light, yellow-green in dark.

Guidelines

Do

  • Show the current value. The bubble only appears while dragging, so put the number somewhere permanent as well.
  • Use a slider when the rough size of the change matters more than the exact number.
  • Give the track enough width that a single step is a visible movement.

Do not

  • Do not use a slider when the exact value matters. Use a number field.
  • Do not use it for more than about twenty steps without also showing the number.
  • Do not ship it without the focus ring. Keyboard users cannot see where they are.
  • Do not shrink the thumb below 24px. That is the AA floor, and it is exactly where the thumb sits.

Accessibility

Every pair passes. The track is measured on its ring, because the ring is its edge. The value bubble is measured on the number inside it, because the number is what it is for; its edge against the page is not what identifies it.

The thumb is right in both themes. Dark mode flips the ring to #FFFFFF on a #211F1C fill, which is exactly what it should do.
  • Build it on a real <input type="range"> where you can, and you inherit keyboard support for free.
  • The focus ring is mandatory. Keyboard users cannot see where they are without it.
  • Arrow keys must move the value, and Home and End should reach the ends.
  • The accessible name must say what is being set, and the value needs a text form if the number is not plain — aria-valuetext for units.
  • The thumb is 24 × 24, which meets WCAG 2.2 2.5.8 Target Size (Minimum) at AA exactly. The 44px figure people quote is 2.5.5, which is AAA. A larger invisible hit area is worth having on touch, but it is not required for AA.

Known gaps

Solid, as a starting point. The track has an edge in both themes, focus and disabled are specified, the keyboard rules are written down, and the range thumbs have a rule for meeting. Verifi is still discovering its full brand, so this can change — together, and always passing AA.
