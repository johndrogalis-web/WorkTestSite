Verifi Design System/Components/Spinner

Spinner

A rotating arc for work whose duration you cannot predict. Three sizes, one colour per theme, and a fixed arc drawn once per size.

Solid3 sizesLight and darkFigma 64411:20735 ↗
The component is the master Spinner, taken as drawn. The arc is a filled shape, so its thickness is fixed per size in the geometry rather than carried on a token — a deliberate choice, not a gap. One colour token flips between themes, and width and height are bound to the size tokens. There is no track ring behind the arc, by design, and nothing here fills with progress. The one thing Figma does not carry yet is the rotation itself; the duration and curve on this page are the spec until the motion is added to the component.

Anatomy

  • FormA stroked arc with a gap. The gap is what makes the rotation visible — a closed ring looks static no matter how fast it turns.
  • SweepAbout 290°, leaving a 70° gap, as drawn in Figma. Starts at 12 o’clock and turns clockwise.
  • EndsFlat, not rounded. Round caps add half the stroke weight at each end, which quietly lengthens the arc past the stated sweep.
  • TrackNone. There is no ring behind the arc, by design.
  • Large40 × 40, token spinner/large
  • Medium24 × 24, token spinner/medium
  • Small16 × 16, token spinner/small
  • ThicknessAbout 5.5 / 4 / 3 at large / medium / small, fixed in the drawing per size. Not a token, by decision.
  • ColourOne token, spinner/fill, flipped per theme
  • Rotation800ms, linear, clockwise, looping without pause. Web value; the Figma motion is being added.

Choosing a size

SizePixelsWhere it belongs
Large40A whole page or a whole panel is waiting.
Medium24A card, a section, a modal body.
Small16Inside a button or beside a line of text.

States

A spinner has one state: spinning. There is no paused, no error and no success variant, so whatever replaces the spinner when the work ends is a separate decision the system does not make for you.

Behaviour

  • Use a spinner when the work cannot report a percentage. If it can, use the Progress bar. The rule is below.
  • Put the spinner where the result will appear, not somewhere else on the page. It marks the thing that is loading.
  • For work that finishes in under about 400ms, show nothing. A spinner that flashes on and off reads as a glitch.
  • Keep one spinner per waiting region. Four spinners on one screen is a stalled page, not a loading page.

Spinner or progress bar

The test is whether the work can report a percentage, not who started it. If something real can be counted — bytes uploaded, rows processed, step 3 of 7 — use a progress bar. If nothing can, use a spinner. A progress bar driven by a timer rather than by the work is worse than a spinner, because it makes a promise about the finish that it cannot keep.

SituationUseWhy
Dashboard card refreshingSpinnerThe request returns when it returns. Nothing to count.
Submitting a slump reading or any single formSpinner, inside the buttonOne request with no measurable stages. Usually short enough that the delay rule below means nothing shows at all.
Uploading a photo or a fileProgress barBytes sent against bytes total is a real number the work produces.
Export, batch job or multi-step syncProgress barStep n of m is countable even when each step is not.
First load of a page or panelSpinnerUnknown duration. A skeleton is the better answer if the layout is predictable.

What initiation does decide

Whether the person started the work or the system did does not change which component you use — but it does change where the indicator goes and how loud it is.

  • The person acted. Put the indicator on or beside the control they touched, and disable that control while it runs. A small spinner in the button, not a spinner somewhere else on the page.
  • The system acted. Put the indicator on the region that is refreshing, and keep it quiet. Background work should not take focus or block anything the person can still read.

How long before showing anything

ElapsedShow
Under 400msNothing. The flash is worse than the wait.
400ms to about 1sSpinner alone.
Past 1sSpinner plus a short line of text saying what is happening.
Past about 10sReconsider the pattern. Words, a stage count, or letting the person leave and be told when it is done.

Once a spinner has appeared, leave it up for at least 400ms even if the work finishes sooner, or fast responses produce the same flicker the delay was there to prevent.

Guidelines

Do

  • Pair the spinner with a short line of text when the wait may be long.
  • Match the size to the area that is waiting.
  • Reserve the space the result will occupy, so nothing jumps when it arrives.

Do not

  • Do not use a spinner for work that can report a percentage.
  • Do not fake a progress bar with a timer. If the number is not coming from the work, it is a lie with a shape.
  • Do not stack a spinner on top of content the person can still read.
  • Do not invent a colour for it. There is one token per theme.
  • Do not let it spin forever. Decide what a timeout looks like.

Specs

  • Sizes40 / 24 / 16. Width and height bound to spinner/{large|medium|small}.
  • Colour, light#171614
  • Colour, dark#FFFFFF
  • Arc thicknessAbout 5.5 / 4 / 3 at 40 / 24 / 16, fixed in the drawing. Not tokenised, by decision.
  • EndsFlat. No round caps.
  • SweepAbout 290° from 12 o’clock, clockwise, as drawn.
  • Track ringNone, by design
  • Duration800ms per rotation, linear, looping without pause. Web value until the Figma motion lands. Linear is deliberate — an eased rotation reads as stuttering, because there is no start or end to ease from.

Accessibility

The spinner passes contrast comfortably in both themes — 18.08:1 in light and 16.44:1 in dark against the product surfaces. The accessibility work here is about motion and announcement, not colour.

  • Give it role="status" and an aria-label, or put visible text beside it.
  • Announce the end of loading as well as the start. A screen reader user who hears “Loading” and then silence does not know it finished.
  • Respect prefers-reduced-motion. This page slows the rotation rather than stopping it, because a frozen spinner reads as a broken page. Worth doing, though the criterion behind it — 2.3.3 Animation from Interactions — is AAA, not AA.
  • Do not rely on the spinner alone to explain a long wait. After a few seconds, words help more than motion.

Known gaps

Solid, as a starting point. Three sizes, one colour per theme, the arc drawn once per size by decision, and the rule for when to use a spinner rather than a progress bar written on both pages. Verifi is still discovering its full brand, so this can change — together, and always passing AA.

Figma housekeeping

Things the design file still has to catch up on. None of them change what is specified here.

  • Add the motion to the Figma component: 800ms per turn, linear, clockwise, looping. When it lands, the note in the component description comes off.

Decided

  • Arc thickness is not a token. The arc is drawn once per size and the thickness lives in the geometry. An earlier stroked rebuild in the playground file is superseded and should not be built from.
  • No track ring behind the arc. By design.
