Table

Dense, comparable records in typed columns, built from three slotted layers: a cell, a row, and rows stacked. This is the surface most of the Hub is made of, so the rules here matter more than anywhere else in the library.

Has gapsCell → Row → Table3 views · 3 statesLight onlyFigma 65889:64833 ↗Walkthrough 65926:21466 ↗
What changed in this version (October 2026). Rebuilt against Table Revised (v3). The middle layer is gone: it is now Table_Cell → Table Row → table, every layer a native Figma Slot. Rows gained a View axis (Basic, Closed, Open) with an Accordion Content slot, and the Disabled state was dropped. The checkbox and radio are now the standalone 24px touch size. The header row never shows a radio and has no hover; header cells do. Row rule is #D0CEC8. New on this page: a How it breaks section with a live resizer for tablet and phone, and the walkthrough’s Do / Do not list. Still light-only in Figma.
What it is. The table is where the Hub does most of its work: tickets, trucks, loads, alerts. Everything in it is a component you already have — a phase tag, a badge, a progress bar, a checkbox — dropped into a cell. The table adds the row, its states and the accordion, and nothing else.

Anatomy

Three layers, and the layering is the whole design. Every layer is a native Figma Slot, so nothing is ever detached.

  • 1 · Table_CellOne cell with its padding built in and a Cell Content slot in the middle. Variants Type = Body, Header, HeaderHover; boolean showSort. Drop text, a Badge, Chip, Tag, Avatar, Progress bar, Checkbox or Button into it. A body cell paints no background of its own.
  • 2 · Table RowHolds the cells in its Row Cell Content slot and owns the background. Variants Type = Body, Header; View = Basic, Closed, Open; State = Default, Hover, Selected. Booleans isSelectable, hasRadioButton, showIcon, and the four chevrons. Extra slots: Icon container, Accordion Content.
  • 3 · TableRows stacked in a vertical auto layout, gap 0, Header first. That is the whole component: there is no separate table frame to configure.
  • Row42px tall, 8px side padding, 8px gap between slots, a 1px #D0CEC8 rule beneath
  • Header rowSame cells with Type=Header; a heavier bottom rule; no radio button even when the body rows have one; no hover or selected state of its own
  • Accordion contentAppears under an Open row on a #DFDEDD container. Key/value rows, a mini table, notes — anything, set to Hug
Why the row owns the background. Hover, selection and the accordion are row-level facts. If each cell painted itself, every one of those states would need a variant per cell type. Cells stay transparent; the row changes colour; everything inside inherits.

Closed / Open

Pick the row type before you fill it. Basic for a plain data list. Closed and Open only when a row genuinely has detail worth hiding. Mixing Basic and Closed rows in one table is allowed, but the chevron column then has gaps, so keep it to tables where only some rows can expand.

How it breaks

Figma draws the desktop table. What happens on a tablet and a phone is a house rule, taken from how the Hub prototypes already do it (the Slump test and Load tables): the table stays a table, columns drop, a chevron column appears, and the dropped columns come back inside the row when it is opened. Drag the handle.

It is never a card. Rows do not turn into stacked cards on a phone; that pattern got pushed back by users. The header stays, the row shows only its top data points, and expanding the row shows the rest.

WidthColumnsChevronWhat happens
≥ 900 desktopAllOnly if the row has Accordion ContentEvery column. Header sticky when the table is taller than the viewport. If columns still overflow, the wrapper scrolls sideways; cell text never wraps.
600–899 tabletMostShownColumns marked droppable leave, lowest priority first (here: Load progress). Header and rows keep their desktop size. The whole row becomes a tap target that opens it.
< 600 phoneThree or fourShownDown to the identifier, the status and the one or two columns the person scans for (here: Truck, Phase, Alerts). Header stays, compact: 12.5px text, 5px cell padding. Long values truncate.

What opens

  • The detail shows the hidden columns, and only those. Label and value, in column order, in the Accordion Content container. Visible columns do not repeat.
  • Actions that lost their column move in too. A delete or an edit that was a cell on desktop becomes a button at the foot of the detail.
  • The whole row toggles. On a tablet or a phone the chevron is the cue, not the only target; tapping anywhere on the row that is not a control opens it.
  • One open at a time on a small screen. Opening a row closes the other, so the list never becomes a wall of detail. On desktop, rows with Accordion Content may stay open together.
  • Give every droppable column a priority in the column definition. Nothing is dropped that was not marked, and the identifier, the status and the alerts never are.
  • Prefer dropping a column to scrolling sideways. Sideways scroll hides the right-hand columns completely; a dropped column is one tap away.
  • Keep the <table> markup at every width. It is the same DOM with columns hidden, so screen readers keep the row and column semantics.

In Angular

For developers. Nothing in this section changes how the Table looks or behaves. If you design in Figma or write the rules, you can skip it.

The three Figma layers map to one component with a column definition. The person building a screen describes the columns and the rows; the component draws the cells, the states, the accordion and the breakpoints.

Behaviour

These are rules, not suggestions. Figma specifies the structure and the states; the rest is house convention and is binding for new work.

Sorting

  • Only columns with showSort sort. One sort at a time; click cycles ascending, descending, off. The arrow shows direction; the header cell hover shows it is clickable.
  • Sort the whole data set, not the page. If the table is paginated, sorting re-queries and returns to page 1.
  • Default sort is the column the person came for — most recent first for tickets, worst first for alerts.

Selection

  • Checkbox for many, radio for one. Never both in one table. The header checkbox selects the page; it never selects the whole data set silently.
  • Clicking the row selects the row when the table is selectable and the click did not land on a control. The checkbox is the indicator, not the only target.
  • Selected survives sorting and paging within a session, and the count is shown somewhere the person can see it.

Expanding

  • The chevron opens the row; nothing else does. The identifier is a link to the detail page, not a toggle.
  • More than one row may be open. Opening a second does not close the first.
  • Accordion content is read-only summary — key/value rows, a mini table, a note — plus at most one action. A form belongs in a Modal / Drawer.

Content

  • Cells do not wrap. Long values truncate with an ellipsis and the full value is in the detail or a Tooltip.
  • Quantities right-align with tabular figures. Everything else left-aligns. Never centre a column.
  • Empty is a dash, not a blank and not “N/A”.
  • Say how many rows there are and paginate past one screen. Infinite scroll loses the footer and the count.
  • The header is sticky on any table taller than the viewport.

Guidelines

Do

  • Fill from the inside out: content → Cell Content → Row Cell Content.
  • Give each column a fixed Table_Cell width and reuse it on every row so columns align.
  • Set Cell Content and Accordion Content to Hug after dropping content.
  • Use View = Basic for simple lists; Closed / Open only when a row needs to expand.
  • Put the identifier first and make it the link.

Do not

  • Do not detach Table_Cell or Table Row to add content — use the slots.
  • Do not build header labels as loose text — use Table_Cell Type = Header, with showSort if the column sorts.
  • Do not recolour rows by hand for hover or selection — switch the State variant.
  • Do not pull from Table v2 DO NOT USE or Table DO NOT USE.
  • Do not use a table to lay out a form, and do not put a second interactive control in every cell — the row is the target.

Accessibility

Cell ink is #171614 on white, 18.08:1, and on the hover and selected tints it stays above 15:1. The selected tint itself is 1.07:1 against the default row, which is why it is a hint and the checkbox is the indicator. The row rule at #D0CEC8 on white is 1.57:1; it separates rows but is not relied on to identify anything.

  • Real <table>, <thead>, <th scope="col">. A grid of divs announces nothing. Keep it at every breakpoint; the phone layout is the same table with fewer columns, never a list of cards.
  • A sortable header is a <button> inside the <th> carrying aria-sort.
  • Every row checkbox or radio has its own label naming the row: “Select truck 45689”, not “Select”.
  • The chevron is a <button> with aria-expanded and aria-controls pointing at the accordion row. Space and Enter toggle it.
  • Selection and open state must be visible without colour. The ticked box and the turned chevron do that; the tints do not.
  • If the wrapper scrolls sideways it needs tabindex="0" and a label so keyboard users can reach it.
  • Focus order is reading order: header controls, then each row’s controls left to right, then into its open accordion content.

Known gaps

  • No dark-mode tokens. Table v3 publishes light only. The dark column under States is derived from the site’s surfaces and is marked so.
  • Header rule width is not a token. The explanation says “bolder bottom border”. This page uses 2px border/strong. Publish it.
  • Striped is on the row definition but has no v3 colour. The old #F0EEEA even-row fill is kept in the Styles snippet behind .striped and is not a Figma value.
  • The walkthrough frame is badged In progress while the page is green. Nothing on it contradicts the components; worth clearing the badge.
  • The breakpoints and the column-drop order are house rules, not Figma. There is no tablet or phone frame on the v3 page. If a designer needs to show one, build it from the same Closed / Open rows rather than a new component.
  • Disabled row has gone. v2 had one; v3 has Default, Hover, Selected only. If a row can be non-interactive, that needs a State.
