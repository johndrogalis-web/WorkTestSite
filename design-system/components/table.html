Anatomy

Three nested components, and the nesting is the whole design. Get this wrong and none of the row states are possible.

  • Table_CellOne cell. Body cells are slot-based with a single state; header cells have default and hover. The cell has no background of its own in a body row.
  • Table_Row_ContentA horizontal wrapper of cells — this is your column definition. Duplicate it, rename it, add or resize cells, then swap it into the row.
  • Table_RowThe full row: background, state, and the four toggles. The row owns the background.
Why the row owns the background. Hover, striping, selection and disabled are all row-level facts. If each cell painted itself, every one of those states would need to be set on every cell in the row and would break the moment somebody added a column. This is the single most important thing to carry into code.

Row slots, left to right

  • Row inset10px from the row edge
  • Checkbox slot24px — Show tableToggle
  • Radio slot24px — Show tableRadioButton
  • Icon slot30px — show rowIcon
  • Row contentYour cells, filling the remaining width
  • Accordion button34px, right-aligned — Show Accordion Button Toggle
Checkbox and radio are mutually exclusive. They appear together in the Figma file only to show that both slots exist. A table offers multi-select or single-select, never both.

Components inside cells

The cell is a container and nothing else. A component dropped into one keeps its own size, its own tokens and its own theme behaviour — the table does not restyle it. This is the arrangement Figma publishes as the showcase table, and it is the fastest way to see whether the newer components agree with each other.

The header row has one state. Its hover belongs to the individual header cell, because hovering a column header is about that column — sorting it, hiding it, resizing it — not about the row.

Behaviour

Which framing to use

Full-bleed

  • Full-bleed for a primary page table. No outer border, no clipping — the page gutters are the table edges.
  • Let it scroll horizontally on narrow screens rather than wrapping cell text.

Boxed

  • Boxed for a table inside a widget or card: 1px border, 8px radius, clipped.
  • Do not mix the two treatments on one screen.

Header controls

  • A kebab menu appears per column on hover, offering hide and sort.
  • Columns drag to reorder.
  • An edge handle resizes.
  • The header is sticky. Scrolling a long table never loses the column names.

Content rules

  • Cells do not wrap. Long values truncate; the full value belongs in the detail drawer.
  • The first column is separated by a 1.5px rule — it is the identifier column and it reads as an anchor.
  • Numbers right-align through the number cell type, never with an inline style.
  • Positive and negative deltas use the signed cell types. Never colour a number by hand.
  • An absent value is an em dash in the soft ink, never an empty cell.
  • Entity links keep the regular weight and family, underlined. Never lime, never mono.

Guidelines

Do

  • Use a table when someone needs to compare records against each other.
  • Right-align anything that is a quantity.
  • Put the identifier in the first column and make it the link.
  • Say how many rows there are, and paginate past one screen.

Do not

  • Do not use a table to lay out a form. That is a grid problem.
  • Do not put a second interactive control in every cell — the row is the target.
  • Do not hide the only copy of a value behind a truncation with no detail view.
  • Do not stripe a three-column table. It adds noise and no help.

Specs

  • Row height42px
  • Cell padding13px vertical, 10px horizontal
  • Row inset10px
  • Header rule2px #4A4F55
  • Row rule1px #DAD8D7
  • Body text14px / 16px, weight 500
  • Caption text12px / 14px, weight 600
  • Cell ink#171614
  • Row checkbox16 × 16, radius 2, stroke #171614, selected fill #211F1C — matches the standalone component
  • Row radio16 × 16, stroke #171614 — matches the standalone component
  • Icon slot30px, icon colour #88888E
  • Accordion button34 × 38
  • Disabled opacity30%

Accessibility

  • Use real <table>, <thead>, <th scope="col"> markup. A grid of divs announces nothing.
  • A sortable header is a <button> inside the <th>, carrying aria-sort.
  • Every row checkbox needs its own label naming the row — “Select truck 4417”, not “Select”.
  • A disabled row must not be reachable by keyboard.
  • Selection must be visible without colour. The checkbox does that job; the background tint alone does not.
  • If the table scrolls horizontally, the scroll container needs tabindex="0" and a label so keyboard users can reach it.
Selected rows at #EEF9FF are a 1.05:1 tint. That is a hint, not an indicator. The checkbox is what communicates selection; the background is decoration on top of it.

Known gaps

The decisions are made; the Figma file has not caught up. Every conflict below has an answer on this page. What keeps the table short of Solid is that the Figma component still carries the old values, and the pagination it depends on has no states.

Decided

QuestionDecisionWhy
TypefaceABC Repro, like everything else. Body 14/16 at 500, captions 12/14 at 600.The Montserrat binding in Figma is the spec-document font leaking into the component.
IconsUnicons, 18px, in the icon ink token. No Font Awesome.One icon library for new work, per the standing rule.
Checkbox and radio16 × 16, the standalone size.One size everywhere.
Selected tint#EEF9FF, which is primary/50 in the product ramp.It looked like a brand colour; it is a product token. No conflict.
BordersReal borders in code: 2px under the header, 1px under each row.Figma draws them as inner shadows, which is a canvas technique, not a spec.
SortOne column at a time. First click sorts ascending (arrow up), second descending (arrow down), third clears. The default sort is named by the page, usually newest first. Sort lives in the URL, like the selected tab, so it survives a refresh.The pattern people already know from every spreadsheet and inbox.
Empty stateSay what would appear here, in one line, and offer exactly one action if the user can create it. Filtered to nothing is different: say the filter is what to clear.The mobile table’s Message component carries this pattern and will become the library empty state.
