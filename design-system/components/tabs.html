Verifi Design System/Components/Tabs

Tabs

Peer views of the same object, switched in place. Tabs are wayfinding, not parameters — nothing is being reconfigured, you are just looking somewhere else.

SolidFigma 39520:6900 ↗
Tabs or segmented control? Tabs switch between views of one object — Overview, Sensors, History for a single truck. A segmented control switches between representations of one dataset — All tickets, Fleet map, Phases. If the page title stays the same and the content below changes shape, you want a segmented control.

States

StateWhat changes
DefaultLabel in --soft, no indicator.
HoverLabel lifts to --strong.
SelectedLabel in --strong, 2px indicator in --select.
Focus2px outline, inset so it does not clip on the track.
PressedNone. Switching is instant, so a pressed state would never be seen for longer than a frame. Selected covers it, the same ruling as Button.
DisabledRare and usually wrong. A view that exists but cannot be opened needs an explanation, not a greyed tab.

Behaviour

  • Switching is instant and lossless. If moving away would discard unsaved input, tabs are the wrong component.
  • The first tab is selected on load. Never open with nothing selected.
  • The selected tab should survive a page refresh — put it in the URL.
  • Past eight tabs the strip scrolls. It never wraps to two rows, and it never collapses into a dropdown.

Guidelines

Do

  • Keep labels to one or two words.
  • Order them by how often they are used, most first.
  • Put the tab in the URL so a view can be linked to.

Do not

  • Do not use tabs for steps in a sequence. That is a stepper, and no stepper component exists — talk to Verifi Design rather than dressing tabs up as one.
  • Do not put a form that spans tabs behind them.
  • Do not wrap tabs to a second row.
  • Do not use tabs and a segmented control on the same screen for the same job.

Specs

  • Padding11px 16px
  • Label14px
  • Indicator2px
  • Track1px
  • Gap2px
  • Selected colourLight #3069E3, dark #E3F200
  • Transition0.14s

Accessibility

  • The strip is role="tablist" with an aria-label; each tab is role="tab" with aria-selected and aria-controls.
  • Only the selected tab is in the tab order — tabindex="-1" on the rest. Arrow keys move between them. This is the standard pattern and users expect it.
  • Home and End jump to the first and last tab.
  • Each panel is role="tabpanel" with aria-labelledby pointing at its tab.
  • The indicator is a 2px line, which is not enough on its own — the label colour change carries the state as well.

Known gaps

Solid, as a starting point. Every state has a value, overflow scrolls and never wraps, the count is capped at eight, and the selected tab lives in the URL. Verifi is still discovering its full brand, so this can change — together, and always passing AA.

Figma housekeeping

Things the design file still has to catch up on. None of them change what is specified here.

  • The private tab item has its own state model that does not quite match the public set. Align it to the states above.
  • Dark mode is not drawn in Figma. The dark values on this page come from the same tokens in dark mode, applied the same way as light. That is the spec until Figma draws it.

Decided against

  • A pressed state. Selected covers it.
  • Wrapping or collapsing past eight tabs. The strip scrolls. Past eight, the page needs rethinking, not the tabs.
