Verifi Design System/Components/Tag

Tag

A small labelled chip with an optional icon and an optional diagonal pattern. The colours are designed to be replaced per instance, which is the interesting part and also the problem.

Has gaps6 combinationsLight and darkFigma 62678:46633 ↗
This component has no fixed palette, and that goes further than the fill. The Figma documentation says the fill and the label colour are changed per instance using selection colours, and the diagonal lines can be recoloured too. The solid diagonal is bound to no variable at all. So no approved colour set exists and every tag anyone makes is an unchecked contrast risk. The values on this page were measured from the Figma documentation frame pixel by pixel, because there was nothing else to read them from. See Accessibility.

States

No interactive states are defined. Whether a tag can be clicked, selected or removed is not answered anywhere in the file, so treat it as a label until someone says otherwise.

Behaviour

  • The icon and the diagonal are independent toggles, so all six combinations are legitimate.
  • The diagonal has two forms because the overlay is sometimes too subtle. Which one to use, and what either of them means, is not written down.
  • The solid form runs straight across the label. Until the file says otherwise, prefer the 35% overlay for any tag whose text has to be read.
  • The label truncates at 100px. What it truncates to, and whether the full text is recoverable, is not specified.
  • Fill and label colour are per-instance overrides, so two tags made by two people will not match unless they agree beforehand.

Guidelines

Do

  • Check the contrast of any fill and label pair you choose. Nothing else will.
  • Keep labels short enough to survive the 100px cap.
  • Agree the meaning of the diagonal within your team before using it.

Do not

  • Do not use a tag where a Truck phase tag belongs. Phases have nine defined colours and meanings; this does not.
  • Do not rely on the diagonal alone to mean anything. It has no defined meaning and no text equivalent.
  • Do not make a tag look pressable unless you have also built the states, because the system has none.

Accessibility

The two default pairs pass. The light one passes by very little, which matters more than usual here because these colours are meant to be swapped by hand.

The examples are worse than the default. The documentation frame in Figma overrides the fill to #2778C1, which measures 4.62:1 — below the 4.83:1 of the #0975C3 default. Anyone who copies an example rather than starting from the component inherits the weaker pair. This page renders the default.
4.83:1 has no headroom. The light default clears 4.5:1 by a third of a point, and the stripe colours are overridable too, so a designer can change three things independently and break the pair without touching the one they were looking at. Measure the composite, not the fill.
  • Measure every fill and label pair you invent. There is no approved list to fall back on.
  • The stripe pattern changes the effective background under the text. Measure against the composited colour, not the base fill.
  • The icon is decorative unless it carries meaning the label does not. If it does, the icon needs a text equivalent.
  • If the tag is ever made clickable it needs a focus style, and none exists.

Known gaps

  • No approved fill and text pairs. Colours are per-instance overrides, so contrast is unenforced by design.
  • The diagonal pattern has no defined meaning. Disabled, pending, estimated? The file shows it without saying.
  • No stated relationship to Truck phase tag, which covers similar ground with nine fixed meanings.
  • letter-spacing: -2 at 12px is bound to the type token here and used nowhere else in the library. Likely a leftover.
  • No icon inventory, and no mapping from icon to meaning.
  • The solid diagonal crosses the label and makes it hard to read. The pattern covers the whole chip, text included, and nothing in the file says how the label is meant to stay legible underneath it. The stripe pitch is not tokenised either, so this page picked one.
  • No truncation rule beyond the 100px cap, and no tooltip fallback.
  • No interactive states, so clickable or removable tags are undefined.
