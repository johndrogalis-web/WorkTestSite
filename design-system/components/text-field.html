Text field

Label, Input and Helper Text in one molecule, 82px tall, six states and one height for every field type. Text Area is the same thing with room for more than one line.

Has gaps6 states26 input/* tokensLight read, dark derivedFigma spec 64764:70684 ↗Components 64749:66005 ↗
What changed in this version (October 2026). Rebuilt against Form Fields v2. Input Field is now a documented molecule of three separate atoms — Label, Input, Helper Text — each with its own written spec. The state set is six (Default, Hover, Focus, Filled, Error, Disabled) with a state-transition table. Field type is configuration, not a component: the old nine-type set collapses to one field plus a placeholder and a trailing icon. Focus is a 2px border plus a ring token. Helper Text reserves its 16px row at all times. Text Area joins this page as the multi-line variant. Search is now its own page.
What it is. The field the Hub asks every question with. Everything about how it looks is a token; everything about how it behaves — when to validate, what the error says, why the label is not optional — is on this page.

Try it

Real fields. Hover for the lifted background and the darker border. Click in for the 2px border and the ring. Type and tab out — the border stays dark because the field is Filled. Type letters into the first one and tab out to see Error: the border, the helper text and its icon turn red together, and the helper row does not move because its 16px was already reserved.

Anatomy

Three atoms in a molecule. Label and Helper Text are defined once and inherited by Input Field, Select, Search, Multi-select and Date picker, so their styling never drifts between field types.

  • LabelBody/sm 14 Regular in label/text-default. Required = True appends an asterisk in label/required-indicator #B00100. Height 10 in the stack. When the field is in Error the label turns red too — driven by the field, never switched by hand
  • Input44px tall, 12 / 16 padding, 8px radius, 1px border (2px on focus), 20px content height. A leading and a trailing 16px icon slot, both hidden by default. Width fills; there are no size variants
  • Helper TextBody/xs 12 in a 16px row that is always reserved, with content or without, so the layout never jumps when an error appears. The Error variant adds a 16px icon ahead of the text
  • StackLabel · Input · Helper with a 6px gap: 10 + 6 + 44 + 6 + 16 = 82px
  • Text AreaThe same molecule with a multi-line box: 98px tall, 64 minimum, text top-aligned, grows with content in code
Field type is configuration, not a component. Email, phone, password, date, number: set the placeholder and swap the trailing icon. Do not build a new component per type.

Behaviour

These are rules, not suggestions. The state machine and the contrast are Figma’s; the validation and copy rules are house convention and binding for new work.
  • Every field has a visible label. A placeholder is a hint, never a name: it disappears when the user types and screen readers do not reliably announce it.
  • Validate on blur, not on every keystroke. Showing an error while the person is still typing the value is the second most common way forms become hostile. The first is moving the layout when the error appears — the reserved helper row stops that.
  • Error copy says what to do. “Enter a date in DD/MM/YYYY” beats “Invalid date”. One sentence, no exclamation mark, no blame.
  • Required is the asterisk plus words. The asterisk alone is not enough; if it matters, the helper says “Required” or the form says which fields are optional.
  • Clear the error as soon as the value is fixed, on the next blur. Do not make the person submit again to find out.
  • Width follows the expected answer. A truck number does not need a full-width field; a street address does. Fields in one column share one width.
  • Disabled means the reason is visible. If the person has to guess why they cannot type, show the reason in the helper or hide the field.
  • Text Area only when more than one line is expected, and it grows with the content. A fixed-height box that scrolls hides what the person wrote.

Guidelines

Do

  • Keep Label switched on, always.
  • Use Input Field for everything; reach for the bare Input only when composing something new.
  • Set the field type by placeholder and trailing icon, not by building a new component.
  • Put format hints in the helper before the person types.
  • Keep the helper row even when it is empty.

Do not

  • Do not use a placeholder in place of a label.
  • Do not compose a label and helper around Input by hand — that is what Input Field is.
  • Do not switch the Label to red yourself; the field’s Error state does it.
  • Do not use Helper Text as a second label.
  • Do not use Text Area where one line will do.

Accessibility

Figma’s own numbers, re-measured here: value text 18.08:1, placeholder 6.24:1, error text 7.37:1 on the field and 6.36:1 on the page. The default border is 5.38:1 against the page surface and every active-state border is darker, so all clear the 3:1 for a boundary. Disabled is exempt (border 1.85:1, text 3.22:1).

  • <label for> wired to the input’s id. Clicking the label focuses the field.
  • Helper text linked with aria-describedby so it reads after the label.
  • Error sets aria-invalid="true" and the message gets role="alert" so it is announced when it appears.
  • The error icon is what keeps WCAG 1.4.1: meaning is not carried by colour alone. Never hide it.
  • The right type and inputmode per field type, so phones show the right keyboard.
  • Focus ring on the field itself, visible against both the white field and the page.
  • Password visibility toggle is a button with a name that changes: “Show password” / “Hide password”.

Known gaps

  • Dark values could not be read. The spec says every state is verified in dark and quotes the numbers (placeholder 6.08:1, error 9.68:1), but the file resolves in light and only the light tokens came back. The dark panes on this page are derived from those numbers and the site’s dark surfaces, and are marked so. Needs a dark-mode frame to read from.
  • Label and value are the same size and weight (14 Regular), so the label does not read as distinct from the value under it. Figma lists this as a known gap carried from gen-2; changing it is a brand decision.
  • label/text-error and label/text-required are referenced by the spec but did not resolve as variables on the component section. This page uses #B00100 for both, matching the helper.
  • Hover background equals the page surface. #F0EEEA on #F0EEEA: on the base surface the hover lift is invisible and only the border change shows. Fine on a white card; worth a slightly different value on base.
