Anatomy

Every field is a label, a box and a helper line stacked 6px apart.

  • Label14px, always rendered
  • Boxmin-height 44px · padding 12px 16px · radius 100px
  • Input text14px / 20px
  • Helper12px, 4px vertical padding, reserved even when empty
  • Gap6px label → box → helper
  • Icon16px, 8px from the text

Behaviour

The error rule, written out

  • The border changes colour. Nothing else does.
  • The alert icon lives in the helper line, left of the message, at 13px.
  • Error text replaces helper text. It never stacks underneath. If the helper text was load-bearing, the error has to carry that information too.
  • Both parts are required. The error variant with no message tells someone that something is wrong but not what.
  • Never dashed, never dotted. There is no dashed or dotted border anywhere in this system, in any state, on any component.

Disabled keeps its value

A disabled field does not blank. It shows what it holds, greyed, because the value is usually the explanation — the plant was set by dispatch, the mix came from the order. Blanking it turns a clear screen into a mystery.

Guidelines

Do

  • Write helper text before the user needs it, not after they fail.
  • Mark required fields and say what happens if they are empty.
  • One field per line for anything typed from memory.
  • Validate on blur or on submit.

Do not

  • Do not use placeholder text as the label. It disappears exactly when it is needed.
  • Do not validate on every keystroke.
  • Do not put the error message anywhere but the helper line.
  • Do not disable submit to communicate a validation failure.

Specs

  • Height44px minimum
  • Padding12px 16px
  • Radius100px
  • Border1px — resting #666054, filled and focus #171614, error #B00100
  • Focus ring0 0 0 2px
  • Disabled fill#DFDEDD, border #B6B1A5, text #7F796C
  • Input text14px / 20px
  • Helper12px
  • Gaps6px vertical, 8px to icons

Accessibility

  • Every field needs a real <label for>. Placeholder is not a label.
  • Link the helper or error text with aria-describedby.
  • Set aria-invalid="true" on the input in the error state.
  • Move focus to the first invalid field on a failed submit, and announce the count.
  • Use the right type and autocomplete so mobile keyboards and password managers behave.
  • The disabled fill at #DFDEDD with text at #7F796C is deliberately low contrast — never put information there that exists nowhere else.

Known gaps

  • Dark mode is not drawn. The dark column here is derived from the surface and ink tokens applied consistently. It is a reading, not a decision.
  • The nine types are loose components, not a variant set. All the states live in a private part underneath, which means an instance can be swapped into a state nobody drew.
  • Text area exists twice — once in the family and once on its own page.
  • Two label positions exist — eyebrow and minimized — with no rule for when to float. Use eyebrow unless a design says otherwise.
