In Angular

The Template and Styles above are what this component renders. The tokens arrive as CSS custom properties on the host, so a theme change never touches the component. The contract below assumes standalone components with the vf- prefix; change the prefix if the team uses another, and nothing else on this page moves.

SelectorInputsOutputsWhat it renders
<vf-toast-outlet (one per app) and a ToastService>The service takes show({ severity, message, action?, actionLabel? }); the outlet takes position (bottom right) and max (3)action (id) when the optional button is pressed, dismissed (id, reason)The outlet is role="region" aria-label="Notifications"; each toast is role="status", errors role="alert". Behaviour

Four severities, and only four. Toast shares its severity grammar with the inline message. There is no fifth, no “critical”, no “notice”.
  • Five seconds by default. Eight when the toast carries an action such as Undo, because the user has to read it and decide. Error toasts do not time out.
  • One stack region per viewport, bottom right, newest on top.
  • Three visible at most. A fourth waits for a slot.
  • Hovering a toast pauses its timer.
  • If the user must act on it, it is not a toast. Use an inline message or a modal.

Guidelines

Do

  • Confirm the thing that just happened, in the past tense, naming the object.
  • Offer Undo in the toast when the action is reversible.
  • Let errors persist.

Do not

  • Do not put the only copy of information in a toast.
  • Do not fire a toast for something the user can already see happening.
  • Do not stack more than three.
  • Do not use a toast to report a validation error on a form the user is looking at — that belongs in the field.

Specs

  • Radius8px
  • Padding13px 15px
  • Font13.5px
  • Icon16 × 16
  • Gap10px inside, 8px between toasts
  • PositionBottom right, 24px from each edge
  • Timeout5s; 8s with an action; errors never
  • Max stacked3
  • Entry0.2s, 6px rise, no bounce

Accessibility

  • The stack region is role="region" with a label; each toast is role="status" so it is announced without stealing focus.
  • An error toast is role="alert" — it interrupts, because it has to.
  • Never move focus to a toast. It is not a place the user asked to be.
  • The close button needs an accessible name.
  • Under prefers-reduced-motion the toast appears without sliding.
  • Five seconds is not enough for everyone to read. Hovering pauses the timer, and the information must exist somewhere else too.

Known gaps

Solid, as a starting point. Four severities, the timing is decided, the action slot is specified, and the stack rules are written down. Verifi is still discovering its full brand, so this can change — together, and always passing AA.
