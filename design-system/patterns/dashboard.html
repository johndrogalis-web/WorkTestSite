Dashboard and widgets

Snapshots of the application, arranged on the page grid in four sizes, editable by drag and drop with a size ladder that keeps the layout sane.

Dashboard / Widget is newly green in Trinity Design System John V: a Widget Shell starting point (Default and Compact density) on Card tokens, a 12-column grid demo with the Large / Medium / Small / Tiny spans, nine widget types drawn at every size, and the edit-mode flow (library, drag, drop, split, rearrange, save). Anatomy

Three things, kept separate on purpose: the page grid (from Page layout), the widget shell, and the widget’s own content.

  • Dashboard gridThe Page Grid inside Main Content: 4 / 8 / 12 / 12 columns by class, 16px inset, 12px gaps. It owns column count, gaps, rows and placement.
  • Widget shellA Card surface: #FEFFFF, 1px #DAD8D7, radius 8, padding 20 (mobile 10), shadow 0 0 3 #4A4F55 12%. Density = Default or Compact.
  • HeaderTitle (Heading/sm 16 Medium), two 24px bordered icon-only buttons, and a secondary small “View all” pill. Compact density drops everything but the title.
  • Body (slot)Whatever the widget is: a chart, a list, a KPI, a map. Lays itself out against the shell’s width with container queries.
  • FooterTimestamp (Body/sm, #7F796C) and a 24px open link to the page the widget summarises. Not in Compact.
  • Widget contentData, charts, metrics, lists or tables. Decides its own minimum usable span.
Widget configuration owns permitted spans. The generic Card component does not know what a KPI needs. Each widget type says which spans it allows per class; the shell just fills what it is given.

Behaviour

These are rules, not suggestions. The Figma flow (65121:13812) and the Dashboard Widgets notes set the editing model and the size ladder. The house rules fill in what the frames leave implicit. Build to this.
  • Snapshots, not pages. A widget shows a slice of one page or section — notifications, hardware alarms, a report — so the person gets a high-level understanding without digging through reports or complex tables. The footer link is how they dig.
  • Size ladder. Large → Medium → Small → Tiny. Splitting a section halves it and both halves step down one size. Tiny does not split. The ladder is the same at every size.
  • Edit mode. “Edit dashboard” (from the setup page) turns it on; editable sections tint blue; the Widget Library opens as a side panel with every available widget, grouped (Concrete quality and specs, Operations, Quick actions).
  • Drag and drop. Drag from the library onto the workspace. An indicator shows where it will land. Drop on a free spot at the lowest level: it takes the space. Drop on top of a section: the section splits in half, the widgets shrink to the next size, and the surroundings rearrange.
  • Rearrange. Move widgets freely in edit mode; the others shift to make room. Spans are clamped to what the widget configuration allows at the current class.
  • Save and exit. “Save changes” persists the layout and leaves edit mode. Cancelling restores the last saved layout. Nothing is saved while dragging.
  • Per class. The saved layout stores a span per class. A chart at 8 of 12 on Large is 8 of 8 on Medium and 4 of 4 on Compact; the widget picks its internal layout from its own width.
  • Refresh. Each widget refreshes on its own schedule and shows “Last updated”. A refresh never reflows the grid.
  • Compact class. At 320–599px every widget spans all four columns and uses its Compact internal layout; Tiny widgets become a two-up row.

Guidelines

Do

  • Give every widget a footer link to the page it summarises.
  • Put the one number that matters in Tiny; put the trend in Small; put enough to decide in Medium.
  • Let widget content respond to the shell’s width with container queries.
  • Keep “Last updated” honest; stale data says so.
  • Define each widget type’s permitted spans in its configuration.

Do not

  • Put a full data table in a Medium widget. That is a Large widget or a page.
  • Give the Card component widget minimums.
  • Let a widget change its own span. The dashboard decides spans; the widget decides layout.
  • Use edit-mode affordances (drag handles, split) outside edit mode.
  • Stack more than two Tiny widgets vertically in one Small slot.

Accessibility

  • Each widget is a region. <section aria-labelledby="<title id>">, so a screen reader can list the dashboard by widget name and jump between them.
  • Headings. Widget titles are <h3> under the page’s <h1> / <h2>; never skip a level because a widget looks small.
  • Icon buttons have names. “Refresh”, “Widget options”, “Open Tickets”. A star glyph means nothing on its own.
  • Edit mode without a mouse. Every drag has a keyboard equivalent: a “Move” option in Widget options with arrow keys, and “Split” / “Remove” as buttons. Announce the new position with a live region.
  • Reading order. DOM order is the visual order left-to-right, top-to-bottom at every class; rearranging in edit mode reorders the DOM, not just the grid placement.
  • Live updates. A refresh updates content silently; only a state change the person asked for is announced.
  • Contrast. Title 18.1:1. The footer timestamp as drawn (#7F796C on #FEFFFF) measures 4.3:1 and fails AA for 14px text; the icon-button border is 1.4–1.6:1. Both are listed under Known gaps and left out of Specs.

Known gaps

  • Light only in Figma. Widget Shell and the widgets have no dark variants; dark values here are derived from the Card and site surfaces.
  • Footer timestamp #7F796C on #FEFFFF measures 4.3:1 — short of 4.5:1 for 14px text. The demo keeps the drawn colour (colour is parked); the fix is one step darker (#666054, 6.2:1) or 16px.
  • Icon-button border #D0CEC8 on #F0EEEA measures 1.6:1 and on #FEFFFF 1.5:1. The control’s boundary is not AA on its own; the 12px icon is. Omitted from Specs as a pass.
  • Empty and Loading are house rules; Figma draws neither.
  • Widget Library and drop indicator are described in the flow but their visual spec (panel width, indicator colour) is not tokenised. Not in the demo.
  • Size names overlap. “Compact” is both a layout class and a widget density; this page says “Compact class” and “Compact density” to keep them apart.
  • Widget spans table gives ranges (“3–4 of 12”). Each widget type still has to commit to a minimum in its configuration.
