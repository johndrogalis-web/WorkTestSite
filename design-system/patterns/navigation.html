Navigation

The Hub’s side navigation — accordion sections with swappable link groups — as a persistent rail on Large and a drawer behind a top bar everywhere else.

What changed in this version (October 2026). New page. Navigation – Hub (Application) is newly green in Trinity Design System John V. The old Accordion and sidebar notes in the project described an earlier rail; this is the rebuilt one: NavAccordionHeader (7 states × Active, light and dark), Nav Link Item, Nav Link Group as a swappable local component, Side Navigation Desktop / Mobile, and Top Navigation Mobile with Default / Search / Nav Open. All colours are nav/* and nav-accordion-header/* tokens; dark values are read from the file, not derived.
What it is. Six product areas and three utilities, always in the same order, always reachable in two taps.

Try it

Click a section header to expand or collapse it; click a child link to make it active. Arrow keys move between headers; Enter or Space toggles; Escape collapses the open section. Only one section is open at a time.

The header is a <button aria-expanded>; the group under it is the disclosure. That is the WAI-ARIA disclosure-navigation pattern the Figma spec cites, and it is why this is an accordion and not a tree.

Anatomy

  • Side Navigation244px wide, 8px padding, two menus with 16px section gap, 10px between items. Breakpoint = Desktop (rail) or Mobile (drawer, 383px, adds the Account block).
  • Nav Accordion SectionA header plus its Nav Link Group. Variants Expanded × Active.
  • NavAccordionHeader240 × 40, padding 12, gap 10, 20px icon, 14/18 label, 20px chevron. States Default, Hover, Focus, Disabled, each crossed with Active. Active adds a 6px left indicator.
  • Nav Link GroupThe children. A local component you swap in per product: build the list from Nav Link Items with gap 0, make it a component, then swap it in the header’s property panel. The accordion’s interactions stay intact.
  • Nav Link Item244 × 34, padding 12 / 12 / 12 / 44. Same states as the header; Active shows a bullet before the label.
  • Top Navigation (Mobile)72px bar below Large: toggle, logo, search and notifications. States Default, Search (the field opens inline), Nav Open (toggle becomes ×).
Why an accordion. The Figma note says it: the section is built on the accordion pattern so children can expand without needing exact placement in prototypes, and so the list under a header can be updated later without rebuilding the component.

Behaviour

These are rules, not suggestions. Figma draws the rail, the drawer, the top bar and every state. The house rules below say how they move. Build to this.
  • Which navigation shows. Large (≥ 1200): the rail, always visible. Below: the 72px top bar; the same menu opens as a drawer from the toggle. See Page layout.
  • One section open. Opening a section closes the other. The section holding the active page is open on load.
  • Header with children toggles; header without children navigates. Both keep the chevron so the rail reads as one list. A header with children does not also navigate; its first child is the landing page.
  • Active is the page, not the click. The header is active when any of its children is the current page; the child link gets aria-current="page" and the bullet.
  • Drawer. Opens from the left over the page with a scrim; the toggle becomes ×; focus moves into the drawer; Escape, the × or the scrim closes it; focus returns to the toggle. The page behind is inert.
  • Drawer closes on navigation. Choosing a link closes the drawer and loads the page. The rail does nothing of the sort.
  • Search in the top bar. The search icon opens the 44px field in place of the logo; Escape or clearing closes it. See Search.
  • Utility menu stays at the bottom. Profile, Settings, Support are pinned; the primary menu scrolls if it must, the utility menu never does.
  • Keyboard. Tab reaches each header and each visible link in order. Up / Down move between headers; Enter / Space toggle; Escape collapses. Home / End jump to the first / last header.

Guidelines

Do

  • Keep the primary menu to the six product areas; add a child, not a section.
  • Give every section an icon from the same 20px set.
  • Keep labels to two words where you can; they must fit one line at 14px in 240px.
  • Use the Nav Link Group swap in Figma rather than detaching.
  • Open the active section on load.

Do not

  • Nest a third level. Children are links, not sections.
  • Put badges or counts in the rail; that is what the notifications bell is for.
  • Let the rail collapse to icons only; there is no icon-rail variant (the “alternate button rail” is an idea, not a component).
  • Make the header navigate and toggle.
  • Change the rail width per page.

Accessibility

  • Landmark. One <nav aria-label="Main"> whether rail or drawer. The utility menu is inside the same landmark.
  • Disclosure. Headers are <button aria-expanded aria-controls>; groups are plain lists of links. No role="tree", no menu roles — this is navigation, not an application menu.
  • Current page. aria-current="page" on the active link (or on the header when it is itself the page). The blue and the indicator are the visual half of that.
  • Toggle. The top-bar toggle has an accessible name (“Open menu” / “Close menu”), aria-expanded, and aria-controls pointing at the drawer.
  • Drawer focus. Focus moves in on open, is trapped while open, returns to the toggle on close; the page behind is inert.
  • Contrast. Light: labels 15.6:1, active 6.4:1. Dark: labels 21:1, active 20.5:1, hover 8.3:1. Light disabled #9B958A on #F0EEEA is 2.6:1 — exempt as disabled (1.4.3), listed under Known gaps.
  • Focus visible. A 2px ring with 4px blur on both themes, plus the background change, so focus does not rely on one cue.

Known gaps

  • Disabled header / link in light measures 2.6:1 (#9B958A on #F0EEEA). Exempt under WCAG 1.4.3 but below the 3:1 the rest of the system keeps for disabled text. Omitted from Specs as a pass; listed here.
  • Dark focus ring #9B958A on #000000 measures 7.1:1 against the rail but only 2.3:1 against the #FEFFD6 10% focus fill it sits on. The border (#E3F200) carries the state; the ring is secondary.
  • Expanded class (840–1199) navigation is product-defined in the Page Layout spec. This page treats it as drawer.
  • No icon-only rail. “Side navigation — Alternate button rail” (65536:21950) is an exploration; not documented.
  • Logo mark. The site has no Verifi mark asset; the demos use the wordmark in text. Drop the SVG in when the brand assets page gets it.
  • Top bar has no Large state in Figma: it only exists as the mobile bar. On Large the search and notifications live in the page header; that placement is a house rule, not a drawn one.
