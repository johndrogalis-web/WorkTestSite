Verifi Design System/Patterns/Page layout

Page layout

Four responsive classes, three breakpoints, one fluid grid that lives inside Main Content. The rules every Hub page is laid out by.

Has gaps4 classes3 thresholdsLight read, dark derivedFigma spec 65601:82539 ↗Breakpoints 64897:58621 ↗
What changed in this version (October 2026). New page, and a new Patterns section of the site. Page Layout is newly green in Trinity Design System John V with a full written spec: Material 3 window-size classes (Compact, Medium, Expanded, Large), thresholds at 600 / 840 / 1200, a 4 / 8 / 12 / 12 fluid grid with 16px inset and 12px gaps, 320 and 1920 as validation widths, and the rule that the grid is calculated from Main Content, not the viewport. The old Spacing and layout foundation page still describes the previous 8-column grid; this page supersedes it.
What it is. The frame every page sits in. Get this right once and every widget, table and form inherits a correct width at every size.

Anatomy

Two layout levels that must stay separate: the application shell, and the Page Grid inside it.

  • Application viewportThe browser window. Minimum supported width 320px.
  • App header / Top navigationCompact, Medium and Expanded: a 72px bar with the navigation toggle, the logo and search + notifications. See Navigation.
  • NavigationLarge: a persistent 244px side rail with 8px padding, 8px from the window edge. Smaller classes: a drawer opened by the toggle.
  • Main contentWhat is left: application width − persistent navigation = main-content width. Background #F6F4F2, 1px #DFDEDD border, inset 8px on #F0EEEA.
  • Page header and controlsTitle, filters and page actions, above the grid, full width of Main Content.
  • Page GridFluid columns inside Main Content: 16px inset each side, 12px column and row gap. Column width = (content width − 32 − (n−1)×12) / n.
  • WidgetsOccupy one or more grid tracks. See Dashboard and widgets.
Why two levels. On Compact and Medium the navigation is hidden, so Main Content can use nearly the whole viewport. On Large the rail takes 244px and the grid is calculated from what remains. If the grid were calculated from the viewport, every widget would be wrong by a rail’s width.

Thresholds are not frame widths. A breakpoint threshold is where the implemented layout changes — the number in the media query. A static Figma frame is one representative width inside a range. Medium behaviour begins at 600px; the Medium frame is drawn at 768px; 768 is not a breakpoint. Nobody writes media queries at 360, 768, 1024 or 1440.

When to add a breakpoint. Only when content or application behaviour needs a meaningful structural change. Never to support a named device.

Behaviour

These are rules, not suggestions. The Figma spec (65601:82539) sets the classes, thresholds, grid and spacing. The house rules below turn them into what a page does when the window changes. Build to this.
  • Breakpoints are the only switches. 600, 840, 1200. The layout does not change anywhere else. Frame widths (360, 768, 1024, 1440) are examples.
  • Navigation. Compact and Medium: hidden, opened as a drawer by the navigation toggle. Expanded: follow the application-shell rule for the product (today: drawer). Large: persistent side rail, 244px.
  • The grid belongs to Main Content. Apply it to the content region, never to the full application frame. It never spans under or across persistent navigation.
  • Fluid columns. Columns are calculated, never fixed pixels. Compact reference: (360 − 32 − 3×12) / 4 = 73px per column.
  • Widgets change span across classes. A chart that is 8 of 8 on Medium may be 6 of 12 on Large. Spans are per class, set by widget configuration (not by the Card).
  • Widget interiors respond to their own width. Container queries, not viewport queries. A widget spanning 4 tracks on Large is narrower than one spanning 8 on Medium and must lay out accordingly.
  • At 320px nothing is lost. No page-level horizontal scroll; widgets go full width; secondary controls may go to an overflow menu; two-dimensional content (a wide table) may scroll inside its own container as a documented exception.
  • At 1920px nothing stretches badly. Columns expand; widgets respect their maximum widths; if the content needs a maximum width, that is decided from this validation, not assumed.
  • Layout spacing is not component spacing. The 16 / 12 / 12 is dashboard density. Card and widget padding is theirs; do not let one leak into the other.

Guidelines

Do

  • Treat breakpoint ranges as implementation rules and Figma widths as documentation examples.
  • Test Compact at 320 and Large at both 1440 and 1920.
  • Apply the Page Grid to Main Content only.
  • Let widget spans differ per class.
  • Use container queries inside widgets.

Do not

  • Add a breakpoint to support a named device.
  • Write media queries at 360, 768, 1024 or 1440.
  • Run the grid under the navigation rail.
  • Give the Card component widget minimums.
  • Mix layout spacing with card or widget padding.

Accessibility

  • Landmarks. One <header>, one <nav aria-label="Main">, one <main>. The drawer and the rail are the same <nav>, shown differently.
  • Reflow (1.4.10). At 320 CSS px no two-dimensional scrolling for the page. Wide tables may scroll in their own box; that exception is documented per page.
  • Skip link. First focusable element, “Skip to main content”, visible on focus, lands on <main>.
  • Zoom. The classes respond to CSS pixels, so 200% browser zoom on a 1440 window behaves as Medium (720). That is intended.
  • Order. DOM order is header, navigation, main at every class, so the reading order never changes when the layout does.

Known gaps

  • Expanded navigation is “product-defined”. The spec defers it to the application-shell rule. This page assumes drawer until a decision is written down.
  • Dark values are from a preview frame (64897:58622), not from nav/page-layout/* dark-mode tokens. Treat them as derived.
  • No maximum content width yet. The 1920 validation exists to decide this; it has not been decided.
  • Alternate button rail (65536:21950, “Page Layout Desktop Idea”) is an exploration on the Figma page, not a variant. Not documented here.
