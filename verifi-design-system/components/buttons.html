Buttons.

A button causes something to happen. If pressing it only takes you somewhere, it is a link, and it should look like one.

The thing that surprises people

The Figma set has four variants and 144 combinations, which reads like an invitation to use them all. The Hub does not. Open any real screen and almost every button is the quiet outline pill — even the one that creates a ticket. Filled buttons appear in perhaps two places in the whole product.

The rule that actually governs: a filled button means this finishes the task and closes what you are in. The Done button at the bottom of a filter popover is one. Everything else — New ticket, Export, Columns, Filters — is an outline pill. If you are adding a solid button to a page, you probably want an outline one.

Same markup, both themes. Note that selected flips from blue to lime: lime is a dark-mode-only selection colour and must never appear as a light-mode fill.

Which variant

VariantUse it whenHow many per container
Quiet (secondary / ghost) Almost always. Toolbar actions, row actions, anything repeated, anything reversible. As many as the layout can carry.
Primary Exactly one high-stakes completion action inside the current visual container — the Done that closes a popover, the Save that ends a flow. One. Never two.
Danger The action destroys data or cannot be undone. Pair it with a confirm step when the loss is permanent. One, and only in a modal or a destructive row action.
Selected Not an emphasis level at all — it shows which of a set of peers you are on. Segmented controls and nav items use it. One per group, by definition.
There is no tertiary. The file does not have one and the product does not need one. If you feel you need a third level of emphasis, you want ghost.

The numbers

  • Height44px
  • Corner radius32px — --radius-pill, which at 44px height renders as a full pill
  • Horizontal padding18px, 20px in a segmented control
  • Label14px / 500 / ABC Repro
  • Gap to icon8px
  • Icon-only44 × 44, still a pill
  • Gap between buttons10px in a toolbar, 8px in a modal footer
  • Transition0.14s on background, border and colour. Nothing bounces.
  • Focus2px --strong outline at 2px offset — never removed, never replaced with a colour change alone

Do and do not

Do

  • Label it with the verb the user is doing: Export, Message driver, Add a ticket.
  • Keep one primary per visual container, at most.
  • Use ghost for anything that repeats down a table.
  • Let the button be as wide as its label needs; do not stretch a row of buttons to match.

Do not

  • Use a button for pure navigation. Use a link.
  • Colour a button by severity. Only danger has a colour, and only for destruction.
  • Put a spinner inside a button by hand — the set has a loading variant.
  • Use yellow. In the product, yellow is dark-mode selection, not a call to action.

Links, which do not exist yet

There is no link component. The tokens are there — interaction/link and link-visited — but nothing is drawn. Until one is, the rule is:

Interim link rule (open item P-15). Inline links use --blue-link #295ccc in light and --strong (white) in dark, underlined, with a 2px offset. In table cells they keep the regular weight and family — never lime, never mono. Visited styling applies in long-form content only, never in app chrome.

Known gaps

  • 46% of the button set’s non-text fills are hardcoded rather than bound to tokens. A theme change today would miss them.
  • The three sizes (large / medium / small) exist as variants but no heights are published for medium and small. Everything in the Hub is the 44px large.
  • No distinct pressed state. Active covers it.
