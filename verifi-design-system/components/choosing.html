Choosing things.

Six controls that all mean “pick something”. They are not interchangeable, and picking the wrong one is the most common mistake in the whole system.

Start here

Answer these in order and you will land on the right control every time.

AskIf yes
Does flipping it change the system immediately, with no Save? Toggle. Dark mode, live updates, a filter that redraws the map.
Can more than one be true at once? Checkbox. Also for a single opt-in confirmation.
Exactly one, and there are two to five options? Radio group. All options visible, no hunting.
Exactly one, and there are five to fifteen options? Dropdown. See form fields.
Are you switching how you look at one dataset? Segmented control. Two to four short options, always visible.
Are you switching between peer views of an object? Tabs — wayfinding, not parameters. See getting around.
Is it an applied filter or a chosen entity that can be dismissed? Chip. If it cannot be removed or selected, you want a tag.
Is precision beside the point and the range bounded? Slider. If the user needs an exact number, pair it with an input or drop it.

The segmented control is where the lime shows itself: selection is blue in light mode and lime in dark, from one token pair. The third checkbox is the indeterminate state.

The two pairs people confuse

Checkbox vs toggle

  • Checkbox sits in a form and waits for Save.
  • Toggle is the save. Nothing follows it.
  • A toggle inside a form with a Save button is a checkbox wearing a costume.

Chip vs tag

  • Chip is interactive — select it, remove it, apply it.
  • Tag is a label. It classifies; you cannot press it.
  • If it has an ×, it is a chip. If it states a status, it is a tag.

How filters actually behave in the Hub

Filters are a composition rather than a component, and the pattern is fixed:

  • The Filters button in the toolbar shows a blue border, a 6% blue background and a count badge when anything is applied.
  • It opens a 380px popover at 16px radius: a head with the title and Reset, a scrollable body of chip groups under uppercase labels, and a foot with the result count and a solid Done button.
  • Applied filters then render as a removable pill strip under the toolbar — Group: value × — ending in a Clear all text button.
  • The result count updates before Done is pressed, so nobody commits to a filter that returns nothing.

The numbers

  • Checkbox / radio16 × 16, 1px border, 9px to the label
  • Checkbox radius2px. Radio is a circle.
  • Toggle40 × 22, 18px knob, 2px inset
  • Chip32px high, 12px padding, 32px radius
  • Segmented item44px min height, 9px / 20px padding, 14px text, 1px internal dividers
  • Segmented group2–4 items, 32px radius, 1px outer border
  • Hit target44px minimum on every one of them, however small the drawn control is

Known gaps

  • The toggle has no hover state — the only atom in the library missing one.
  • The slider has no disabled and no focus state.
  • The segmented control’s variants are still called Primary and Variant2, and one item has both “default” and “Default” as distinct values.
  • The checkbox calls the third state “intermediate” in one place and “isIndeterminate” in another. The concept is indeterminate.
