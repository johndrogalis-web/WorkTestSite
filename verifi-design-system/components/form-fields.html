Form fields.

One pill-shaped input, drawn in six states, carrying nine different kinds of data. Get this component right and most of the product is right.

Three parts, 6px apart

Every field is a label, a box and a helper line, stacked with 6px between them. The helper line is always present in the layout even when it is empty, so fields in a row keep their baselines when one of them goes into error.

  • Label14px, always rendered. Two positions exist in Figma — eyebrow (above, at rest) and minimized (floated). Use eyebrow unless the design says otherwise.
  • Boxmin-height 44px · padding 12px 16px · radius 100px
  • Input text14px / 20px line-height
  • Helper12px, 4px vertical padding, reserved even when empty
  • Gap6px label → box → helper
  • Icon16px, 8px from the text on either side

The error rule, written out

This is the part people get wrong, so it is worth being exact.

  • The border changes colour. Nothing else does. No red fill, no red text in the input, no icon inside the box.
  • The alert icon lives in the helper line, to the left of the message, at 13px.
  • Error text replaces helper text. It never stacks underneath it. If the helper text was load-bearing, the error message has to carry that information too.
  • The error state needs both parts. The field’s error variant on its own, with no message, tells the user that something is wrong but not what.
  • Never dashed, never dotted. There is no dashed or dotted border anywhere in this system, in any state, on any component.

Disabled keeps its value

A disabled field does not blank. It shows what it holds, greyed, because the value is usually the explanation — the plant was set by dispatch, the mix came from the order. Blanking it turns a clear screen into a mystery.

Search behaves differently

Search in the Hub is a lookup across trucks, customers, order numbers, mixes and reports, and its suggestion box has eleven layouts. The behaviour the variants describe:

  • Focus with nothing typed shows recent searches.
  • A typed prefix routes to a typed result group — a truck number and a customer name produce different result lists, not one merged list.
  • No matches shows No hit, and offers Did you mean when something is close.
  • A long result set ends with Show all rather than scrolling forever.

Do and do not

Do

  • Write helper text before the user needs it, not after they fail.
  • Mark required fields with the asterisk and say what happens if they are empty.
  • Keep one field per line for anything a person types from memory.

Do not

  • Use placeholder text as the label. It disappears exactly when it is needed.
  • Validate on every keystroke. Validate on blur, or on submit.
  • Put the error message anywhere but the helper line.
  • Disable the submit button to communicate a validation failure — say what is wrong.

Known gaps

  • The nine types are loose components, not a variant set. All the states live in a private part underneath, which means an instance can be swapped into a state nobody drew.
  • Text Area exists twice — once in the family and once on its own page.
  • The public dropdown set has no focus state.
  • Dark mode is not drawn for any of them.
